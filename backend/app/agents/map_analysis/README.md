# 지도 분석 도구 (map_analysis)

좌표와 검색어를 받아 **반경 안에 그게 몇 개 있고 제일 가까운 게 어디인지** 답한다.

분석 에이전트가 아니라 **도구**다. `AgentAnalysis` 를 만들지 않고 `AgentId` 에도 없다.
최종판단이 업종 후보를 정한 뒤 필요할 때 부른다.

## 왜 있나

다른 세 에이전트가 보는 자료는 전부 분기 단위 과거 통계다. 최종판단이 업종을 고르면서
"지금 실제로 어떤지" 확인할 자리가 없었다.

세는 대상이 다른 것도 크다. 강남역 반경 500m 기준으로 상가업소(sbiz)는 5,182곳인데
그중 경영컨설팅 694 · 회계세무 405 · 광고 386 · 법무 382로 사무실이 1,800곳 넘는다.
빌딩 안 사업자까지 잡히기 때문이다. 임대인에게 "경쟁 상대 5,182곳"은 의미가 없다.
카카오는 지도에 등재된, 손님이 찾아갈 수 있는 곳만 센다.

## 쓰는 법

```python
from functools import partial
from app.agents.map_analysis import search

# 오케스트레이터가 좌표를 묶어서 넘긴다. DecisionRequest 에는 좌표가 없다
tool = partial(search, task.site, radius_m=task.radius_m)

result = await tool(["한식", "치킨", "지하철역"])
```

```bash
python examples/run_map_analysis.py --address "서울 강남구 테헤란로 152" \
    --query 치킨 --query 편의점 --query 초등학교
```

## 검색어 쓰는 법

**지도에서 사람이 검색하는 말로 쓴다.**

| 쓴다 | 쓰면 안 된다 |
| --- | --- |
| `한식` · `치킨` · `커피` · `약국` · `미용실` | `한식 음식점업` · `비알코올 음료점업` |

팀 공통 75중분류 이름을 그대로 넣으면 **72개가 0건**으로 나온다. 통계청 표준산업분류
이름이라 카카오 색인에 그런 말이 없다. `한식 음식점업` → 0, `한식` → 283.

아래 말은 카카오 18종 분류로 자동 전환된다(`CATEGORY_CODES`). 별칭도 받는다 —
`초등학교`·`중학교`·`고등학교`·`대학교`는 `학교`로, `어린이집`·`유치원`은 한 분류로 간다.

```
대형마트 · 편의점 · 어린이집,유치원 · 학교 · 학원 · 주차장 · 주유소,충전소 · 지하철역
은행 · 문화시설 · 중개업소 · 공공기관 · 관광명소 · 숙박 · 음식점 · 카페 · 병원 · 약국
```

이 전환이 중요하다. 키워드로 물으면 **지하철역이 14 vs 2, 학교가 6 vs 1** 로 부풀고
**대형마트는 0** 이 나온다. 상호에 그 말이 든 가게까지 걸리기 때문이다.

## 결과 읽는 법

```json
"편의점": { "count": 49, "sampled": 15, "matched": 15,
           "nearest": {"name": "세븐일레븐 강남파이낸스점", "distance_m": 36},
           "brands": {"GS25": 7, "세븐일레븐": 4, "CU": 3, "이마트24": 1} },
"치킨":   { "count": 69, "sampled": 15, "matched": 2,
           "nearest": {"name": "치킨공식", "distance_m": 133} }
```

| 필드 | 뜻 | 믿어도 되나 |
| --- | --- | --- |
| `count` | 반경 안 전체 개수 | **전수다.** 목록 상한(45건)과 무관 |
| `sampled` / `matched` | 표본 몇 건을 봤고 그중 몇 건이 실제로 그 분류였나 | `count` 를 얼마나 믿을지 판단하는 값 |
| `nearest` | 제일 가까운 한 곳 | 분류가 맞은 것 중에서만 고른다 |
| `brands` | 브랜드별 개수 | **표본 기반이라 전수가 아니다** |

**`matched` 가 `sampled` 보다 한참 적으면 `count` 를 그대로 쓰면 안 된다.**

카카오 키워드 검색은 "치킨집"이 아니라 "치킨과 연관된 곳"을 준다. 메뉴에 치킨이 있거나
태그가 걸린 집까지 센다. 위 예에서 편의점은 15/15라 49를 믿어도 되지만, 치킨은 2/15라
69가 치킨집 개수가 아니다. `count` 자체를 고칠 방법은 없다 — 목록이 45건에서 잘려
전수를 세서 걸러낼 수가 없다. 그래서 숫자 대신 **숫자의 신뢰도**를 같이 낸다.

분류 조회(18종)는 카카오가 이미 걸러 준 결과라 `matched` 가 항상 `sampled` 와 같다.

## 한계

- **브랜드는 표본 15건에서만 센다.** 밀집 지역에서는 놓친다. `category_name` 마지막
  조각이 가게 이름의 앞부분과 같을 때만 브랜드로 본다 — `스타벅스 강남점`은 걸리고
  `농민백암순대 강남직영점`의 "순대"는 안 걸린다. 어림짐작이라 상호를 다르게 쓰는
  브랜드는 놓친다.
- **`count` 는 조회 시점 값이다.** 기준 기간이 없어 `queried_at` 만 남긴다.
- **결과가 기록에 남지 않는다.** 도구라서 `source_analyses` 에 안 실리고
  `evidence.path` 로 인용할 수 없다. 리포트에 숫자로 찍혀야 하면 `AgentAnalysis` 를
  반환하는 진입점을 따로 붙여야 한다.

## 설정

카카오 REST 키는 주소 변환과 같은 `GEOCODING_API_KEY` 를 쓴다. 새 키가 필요 없다.

| 환경변수 | 기본값 | |
| --- | --- | --- |
| `GEOCODING_API_KEY` | — | 카카오 REST 키 |
| `MAP_ANALYSIS_MAX_CONCURRENCY` | 4 | 동시 요청 상한 |

`sample_size` 는 15가 상한이다. 카카오가 한 페이지에 15건까지만 준다.
