## AI 분석

코드를 읽으면 "실패를 삼킨다"거나 "AI 권한이 너무 작다"고 보일 수 있지만 일부러 이렇게 만든 부분입니다. 경로는 `backend/app/` 기준입니다.

### AI에게 맡기는 범위

| 지금 동작 | 이렇게 둔 이유 | 위치 |
| --- | --- | --- |
| AI 판단(L)은 100점 중 10점이고, 나머지 90점은 코드가 계산합니다. | 같은 주소에서 순위가 크게 흔들리지 않게 하려는 것입니다. AI는 코드가 볼 수 없는 조건만 봅니다. 배점을 올리는 조건은 [채점표](decision-prompt-rubric.md)에 적어 두었고 자동으로 올리지 않습니다. | `domain/code90.py`, [README](../README.md) |
| AI는 업종마다 근거와 방향(유리·불리·중립)만 고릅니다. 등급 숫자와 근거 문장은 코드가 만듭니다. | AI가 등급을 직접 적으면 근거 개수와 맞지 않는 점수가 나올 수 있습니다. | `domain/l_record.py`, `domain/report.py`의 `l_grade` |
| 층과 필수·선호 설비는 AI 판단 근거로 쓰면 거절합니다. | 코드가 이미 점수와 추천 제외에 반영한 조건입니다. 같은 사실을 두 번 세지 않습니다. | `domain/report.py`의 `rule_scored_space` |
| 보고서·지적 문장에 숫자를 직접 쓰면 제출을 거절합니다. | 숫자는 저장된 사실을 가리키는 칸으로만 넣게 해서, AI가 숫자를 지어내거나 잘못 옮기는 것을 막습니다. 화면의 숫자는 서버가 원자료 값으로 채웁니다. | `application/report.py`의 `validate_proposal`, `ai/evaluators.py` |
| 제출을 거절할 때 AI가 보낸 문장은 되돌려 보내지 않고, 틀린 칸의 위치와 고치는 법만 알려 줍니다. | 사용자 입력과 비밀값이 오류 안내를 타고 기록에 남지 않게 하려는 것입니다. | `ai/tools.py`의 `validation_message` |

### 실패했을 때

| 지금 동작 | 이렇게 둔 이유 | 위치 |
| --- | --- | --- |
| 평가자 한 명이 실패해도 분석을 멈추지 않습니다. 네 칸을 그대로 두고 실패한 칸과 완료율(예: 0.75)을 결과에 남깁니다. | 평가자 한 명 때문에 보고서 전체를 버리지 않습니다. 실패를 동의로 세지도 않습니다. | `ai/runtime.py`의 `review_and_finalize`, `ai/evaluators.py` |
| 손님 평가자는 모델 호출이 실패해도 완료로 남습니다. | 손님 평가자의 채점과 판정은 코드가 하고, 모델은 남은 지적 칸만 채우기 때문입니다. 모델 상태는 따로 기록합니다. | `ai/evaluators.py`, `ai/customer_rubric.py` |
| 평가 의견을 최종 보고서에 반영하지 못해도 분석은 "완료"로 끝납니다. 보고서 한계 칸에 "피드백 최종 반영을 완료하지 못했습니다"를 표시합니다. | 완료된 평가 내용과 코드 점수는 유효합니다. 실패를 숨기지 않고 사용자에게 알리는 쪽을 골랐습니다. | `ai/runtime.py`의 `review_and_finalize` |
| 예산(호출·토큰·시간)이 차거나, 새 정보 없는 호출이 세 번 이어지거나, 도구를 한 번에 하나만 부르는 규칙을 어기면 오류 대신 코드 점수로 보고서를 마무리합니다. | 비용과 시간에 상한을 두되, 그때까지 확인한 판단은 살립니다. 마무리한 이유는 한계 칸에 적습니다. | `ai/runtime.py`의 `fallback`, `ai/budget.py` |
| 자문역 호출이 실패하면 decision이 혼자 판단하고 계속 진행합니다. | 자문은 점수를 매기지 않는 보조 의견입니다. 자문 없이 판단했다는 사실은 결과에 남깁니다. | `ai/advisor.py` |

### 예산과 반복

| 지금 동작 | 이렇게 둔 이유 | 위치 |
| --- | --- | --- |
| 평가 의견 반영은 한 번만 합니다. | 여러 번 돌리면 초안이 근거보다 평가자 지적에 맞춰 흔들립니다. 대신 지적마다 받아들임·일부·기각과 이유를 남깁니다. | `ai/runtime.py`, [TECH_DECISIONS](TECH_DECISIONS.md)의 알려진 한계 |
| 평가자의 입력 몫(4만, 심사관 7만 토큰)은 읽기 단계에만 엄격합니다. 읽기 세 번을 마쳤거나 제출이 거절된 뒤의 제출 호출은 분석 전체 상한까지 씁니다. | 읽은 뒤에는 제출까지 가게 하려는 것입니다. 다른 평가자의 몫은 빌리지 않습니다. | `ai/budget.py`의 `submitting`, `ai/evaluators.py` |

실제 모델로 잰 결과와 아직 남은 문제는 [같은 주소 반복 분석 실측](consistency-live-report.md)에 있습니다. 그 문서에 적힌 문제는 의도가 아니라 이미 고쳤거나 고칠 대상입니다.
