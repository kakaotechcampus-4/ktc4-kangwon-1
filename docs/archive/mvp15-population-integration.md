# MVP1.5 인구 분석 연결 · 2026-09-28

## 반영 범위

- 작업 브랜치: `feature/mvp-1.5-orchestra`
- `origin/feature/population-blocks`의 `5daa268`만 커밋 없이 적용했다.
- 프론트·DB 변경을 포함하는 브랜치 전체 병합은 하지 않았다.
- 공통 스키마와 `floating_population` 에이전트 ID는 유지한다.

## 연결 구조

`AnalysisTask.radius_m` → 기존 인구 `analyze()` → `AgentAnalysis.data` → 최종판단

| 블록 | 자료와 의미 |
| --- | --- |
| `population` | 서울시 API의 유동 통행량. 고유 방문자 수가 아님 |
| `resident` | 동봉 CSV의 상주인구·가구 자료 |
| `worker` | 동봉 CSV의 직장인구 자료 |
| `population_summary` | 세 자료가 모두 있는 상권 교집합의 비교 지표 |
| `interpretation` | 코드가 만든 요약 문장과 원지표 경로 |

별도 인구 에이전트 세 개를 등록하는 구조가 아니다. 기존 인구 분석 함수가 블록을 함께 생성한다.
반경은 상권 선택에 사용하지만 걸친 상권 전체를 집계하므로 정확한 반경 내부 인구 수는 아니다.

## 추가 정비

- 최종판단 프롬프트에 새 블록·단위·분모·기간·근거 경로 해석을 추가했다.
- 통행량과 인구 수의 합산, 상주·직장 인구의 중복 미확인 합산을 금지했다.
- 인구 종합 비율은 전체 합계가 아닌 교집합 기준으로 해석한다.
- 평균 가구원 수만으로 1인 가구 비중을 확정하지 않도록 제한했다.
- 기존 입력 축약 코드가 새 블록을 그대로 전달하므로 별도 변환 코드는 추가하지 않았다.
- 배포 패키지에 `floating_population/data/*.csv`를 포함했다.

## 검증 결과

Python 3.12.14, 외부 API·LLM 대역 사용.

- 백엔드 `unittest`: 364개 통과.
- `validation_tool` 테스트: 20개 통과.
- Ruff 검사 및 변경 Python 파일 포맷 검사 통과.
- mypy: 71개 소스 파일 통과.
- 실제 인구 계산 결과를 최종판단에 전달하여 반경 300m, 새 블록 보존, 근거 경로 검증을 확인했다.
- CSV 누락 시 유동·직장 자료 유지, null 근거 거절, 기간 차이의 `limitations` 전달을 확인했다.
- wheel을 빌드하고 소스 경로 밖에서 상주 CSV 1,633행·직장 CSV 1,641행을 읽었다. 두 스냅샷의 공표 분기는 `20262`다.
- 기존 FastAPI 테스트에서 Starlette의 httpx 사용 중단 예정 경고가 발생한다. 테스트 실패는 아니다.

## 남은 확인

- 실제 API·LLM으로 새 인구 블록을 이용한 판단 품질은 이번에 검증하지 않았다.
- 스냅샷 공표 분기와 실제 인구 관측 시점은 구분해야 한다.
- 인구 분석의 `interpretation`에는 평균 가구원 수로 가구 유형을 추정하는 문구가 있다. 최종판단에는 단정 금지 규칙을 추가했지만, 원문을 직접 표시한다면 담당자와 문구를 점검해야 한다.
- 인구 보완 함수·사용자 질문·LangGraph는 추가하지 않았다.
- 커밋·푸시하지 않았다. 가져온 변경은 스테이징되어 있으며 추가 정비는 미스테이징 상태다.
