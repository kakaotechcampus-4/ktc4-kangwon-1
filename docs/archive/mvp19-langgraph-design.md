# MVP1.9 · LangGraph 전환 설계

## 목표와 범위

기존 오케스트레이터의 실행 흐름을 LangGraph로 옮긴다. 분석 결과, 모델 호출 계약, 저장과 오류 처리는 유지한다.

- 현재 브랜치: `feature/mvp-1.5-orchestra`. 인구 통합 기준 커밋은 `7a8e514`다.
- 개폐업은 폴리곤 기준을 유지한다. 반경 분석으로 바꾸지 않는다.
- 이번 단계에는 사용자 질문·재개, 체크포인트 DB, 새 HTTP API, 건축물·법률 연계를 넣지 않는다.
- 커밋·푸시는 하지 않는다.

## 선택한 방식

`run_react()`의 외부 계약을 유지하고 내부 실행을 `StateGraph`로 교체한다. 분석·판단·보완 함수는 재사용한다.

| 대안 | 판단 |
| --- | --- |
| 기존 실행 전체를 노드 하나로 감싸기 | 변경은 작지만 보완 분기가 그래프에 드러나지 않아 제외 |
| 실행 단계와 보완 분기를 그래프 노드로 분리 | 채택. 기존 동작을 보존하면서 다음 단계의 질문 분기를 연결할 수 있음 |
| LangChain 에이전트까지 전면 교체 | 모델 호출과 도구 계약까지 바뀌므로 이번 범위에서 제외 |

## 실행 흐름

1. 입력 검증 후 `choose_action`에서 기존 오케스트레이터 모델을 호출한다.
2. 올바른 `prepare_address` 호출이면 기존 주소 준비 함수와 저장 콜백을 실행한다.
3. 다음 모델 호출에서 `run_analyses`를 선택하면 기존 `run_agents()`로 세 분석을 병렬 실행한다.
4. `make_decision`을 선택하면 `evaluate_decision`에서 기존 최종판단 함수를 실행한다.
5. 최종 결과면 종료한다. 보완 요청이면 `execute_supplement`에서 등록된 부분 작업만 실행한다.
6. 보완 실행 후 `evaluate_decision`으로 돌아간다. 두 번째 판단에는 보완 작업 목록을 제공하지 않는다.

잘못된 도구 이름·순서·인자는 기존처럼 오류 관찰을 메시지에 붙이고 `choose_action`으로 돌아간다.
거절·도구 호출 누락·복수 도구 호출 등 기존 즉시 실패 조건도 유지한다.

## 유지할 동작

- 오케스트레이터 모델 최대 6회. 그래프 노드 실행 횟수와 별도 카운터로 관리한다.
- 보완 최대 1라운드. 모든 분석을 재실행하지 않고 요청된 작업만 실행한다.
- 최종판단 출력 교정 1회는 기존 최종판단 코드에 그대로 둔다. 데이터 보완 횟수와 구분한다.
- `partial`이라는 이유만으로 보완하지 않는다. 기존 판단 기준과 작업별 실행 가능 조건을 유지한다.
- 보완 실패·미채택 시 원본을 보존한다. 계약 위반·저장 실패는 종료 오류로 전파한다.
- 분석 병렬 실행은 기존 `run_agents()`를 사용한다. 개별 완료 즉시 저장하며, 계약 오류가 있어도 시작된 다른 분석을 수집한 뒤 오류를 전달한다.
- 주소·반경·요청 ID는 모델이 변경할 수 없다.
- 모델·API 호출에 그래프 자동 재시도를 새로 적용하지 않는다. 호출 비용과 저장 중복을 방지한다.
- 타임아웃·취소 처리와 서비스의 최종 저장 트랜잭션을 유지한다.

## 상태와 의존성

그래프 내부 상태는 `TypedDict`로 정의한다. 외부 공통 `schemas.py`는 변경하지 않는다.

- 상태: 대화 메시지, 모델 호출 횟수, 준비된 `AnalysisTask`, 분석 결과, 판단 결과 또는 보완 요청, 보완 여부, 피드백·보완 이벤트.
- 주소 변환 함수·모델 함수·분석 등록·저장 콜백·설정은 실행 의존성으로 주입한다. 상태에 키나 클라이언트 객체를 넣지 않는다.
- 메시지는 기존 OpenAI 형식을 유지한다. LangChain 모델 래퍼로 바꾸지 않는다.
- 각 요청은 독립 상태로 실행한다. 공유되는 변경 가능 상태를 만들지 않는다.
- 의존성은 LangGraph만 직접 추가한다. 설치되는 하위 의존성과 기존 OpenAI·Pydantic 호환성을 확인한다.

## 파일 변경 범위

| 파일 | 변경 |
| --- | --- |
| `backend/app/agents/orchestration/graph.py` | 내부 상태·노드·조건 분기 정의 |
| `backend/app/agents/orchestration/workflow.py` | `run_react()`를 그래프 실행 진입점으로 변경. 주소 준비·분석 실행·등록 함수 유지 |
| `backend/app/agents/orchestration/supplement.py` | 기존 보완 실행·채택 규칙을 재사용할 수 있게 판단과 실행 경계 분리. 중복 루프는 남기지 않음 |
| `backend/pyproject.toml` | 검증한 LangGraph 의존성 범위 추가. 기존 CSV 패키지 설정 유지 |
| 관련 오케스트레이터·서비스 테스트 | 그래프 분기와 기존 계약 회귀 검증 |
| `validation_tool` 관련 테스트·안내 | 기존 실행 명령과 trace 계약의 유지 확인. 필요한 연결 수정만 수행 |
| 백엔드 실행 안내 | 의존성 설치와 전환 범위 기록 |

분석 에이전트, 최종판단의 분석 로직, DB 테이블, 프론트엔드, HTTP 계약은 변경하지 않는다.
서비스와 validation tool은 기존 `run_react()`·콜백을 유지하므로 실행기 교체만으로 연결되는 것을 목표로 한다.

## 검증과 완료 조건

Python 3.12 `chaeum` 환경에서 API·LLM 대역으로 검증한다.

- 같은 입력·같은 대역 응답으로 기존 결과, 모델 호출 순서·횟수, 저장 이벤트를 유지한다.
- 보완 없는 종료, 성공·실패·거절·미채택 후 재판단을 확인한다.
- 6회 호출 제한과 1라운드 보완 제한을 각각 검증한다.
- 주소 실패, 부분 분석, 계약 오류, 저장 콜백 실패, 취소·타임아웃의 기존 처리를 유지한다.
- 동시 요청의 상태가 섞이지 않는지 확인한다.
- 새 인구 블록과 원본 근거 경로가 최종 결과까지 유지된다.
- DB 재조회와 validation trace로 결과·보완 이력을 확인한다.
- 백엔드·validation 테스트, Ruff·포맷·mypy를 실행한다. 실제 LLM의 출력 일치까지 주장하지 않는다.

이번 단계의 완료는 그래프 실행으로 기존 결과와 실패 처리를 보존하는 것이다. 영속 중단·재개는 아직 지원하지 않는다.

## 다음 단계: 선택적 질문·재개

전환 검증 후 별도 설계한다. 질문은 필수가 아니며 임대인이 답할 수 있고 판단에 필요한 정보만 요청한다.
그때 질문·답변 계약, 미응답·건너뛰기 정책, 체크포인트, 요청별 재개 식별자와 중복 저장 방지를 함께 정한다.
