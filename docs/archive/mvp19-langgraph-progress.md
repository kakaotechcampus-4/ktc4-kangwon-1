# MVP1.9 LangGraph 전환 결과

## 변경 범위

- 기준 커밋: `7a8e514` 인구 통합. 작업 브랜치: `feature/mvp-1.5-orchestra`.
- `run_react()` 호출 방식은 유지하고 내부를 LangGraph로 교체했다.
- `graph.py`에 도구 선택·주소 준비·분석 병렬 실행·최종판단·보완 노드를 구성했다.
- `supplement.py`는 부분 작업 실행·검증·채택을 담당한다. 판단과 재판단 순서는 그래프에서 관리한다.
- 기존 수동 실행 루프와 `decide_with_supplement()`의 중복 판단 루프는 제거했다.
- 분석 에이전트, 최종판단 분석 로직, 공통 스키마, DB 테이블, HTTP API, 프론트엔드는 변경하지 않았다.

## 보존한 계약

- 오케스트레이터 모델 최대 6회, 보완 최대 1라운드, 최종판단 출력 교정 최대 1회.
- 주소·요청 반경·ID는 코드가 통제한다. 개폐업은 폴리곤 기준을 유지한다.
- 세 분석은 기존 `run_agents()`로 병렬 실행하며 완료 즉시 기존 콜백으로 저장한다.
- 보완은 제시된 작업만 실행한다. 실패·거절·미채택 시 원본을 보존하고 재판단한다.
- 계약 위반·DB 실패는 성공으로 숨기지 않는다. 타임아웃·취소 처리도 유지한다.
- 기존 validation 명령, 단계명, attempt, 보완 이벤트와 DB 기록을 유지한다.
- 서비스에 보완 함수를 주입하지 않으면 보완은 실행하지 않는다. HTTP의 보완 등록 정책은 변경하지 않았다.

## 환경·검증

- Python 3.12.14 `chaeum`, LangGraph 1.2.12. 프로젝트 의존성 범위 `>=1.2.12,<1.3`.
- `pip check`: 충돌 없음. LangGraph 하위 의존성은 설치하지만 LangChain 모델 래퍼는 사용하지 않는다.
- 백엔드 unittest 369개, validation 테스트 20개 통과.
- Ruff, 변경 Python 파일 포맷, mypy 72개 소스 검사 통과.
- 실제 그래프 노드 순서, 6번째 호출 정상 종료, 저장 콜백 실패 시 나머지 분석 수집, 동시 요청 분리를 추가 검증했다.
- 기존 보완 테스트로 두 번째 보완 거절, 원본 보존, 보완 저장 실패, 취소 시 이력을 확인했다.
- 실제 API·LLM은 호출하지 않았다. 실제 모델의 판단 품질은 별도 검증 대상이다.
- 독립 코드 검토에서 수정이 필요한 문제는 발견되지 않았다. 검토자가 오케스트레이터 22개·보완 20개 테스트를 별도로 재실행했다.

## 범위 결정과 다음 단계

- 사용자 승인대로 기존 브랜치에서 작업했다. 별도 worktree는 만들지 않았다.
- LangSmith 외부 자동 추적은 명시적으로 비활성화했다. 주소와 분석 자료는 기존 로컬 trace·DB 정책을 따른다.
- 호출자가 별도로 외부 추적 콜백을 주입하는 경우까지 차단하는 기능은 아니다. 현재 서비스는 이를 주입하지 않으며 향후 추가 시 개인정보 검토가 필요하다.
- 실제 모델 품질·실서비스 성능·배포 환경 전체 검증은 수행하지 않았다.
- 그래프 상태는 메모리에만 있다. 사용자 질문·체크포인트·중단 후 재개는 아직 구현하지 않았다.
- 인구 보완 함수, 건축물·법률 연계는 추가하지 않았다.
- 이번 LangGraph 변경은 커밋·푸시하지 않았다.
