# 리포트 구성 요약 (검토용)

작성: 2026-10-02 · 자세한 설계: [report-plan.md](report-plan.md)

## 왜 바꾸나
지금 리포트는 업종마다 점수 · 이유 · 근거 경로 · 위험뿐입니다.
실측(오금로 404)에서 평가자 4명이 짚은 것은 "틀렸다"가 아니라 **"빠졌다"**였습니다.

| 평가자 | 빠진 것 |
| --- | --- |
| 동네 손님 | 주 고객층, 이용 시간대 |
| 예비 창업자 | 교체율, 경쟁 강도 |
| 심사자 | 근거 신뢰도(표본이 작음) |
| 임대인 대변인 | 설비·공간 조건 |

→ 이 항목들을 **업종마다 같은 틀로** 쓰게 합니다.

## 리포트 구성

| 구역 | 내용 |
| --- | --- |
| A. 한 줄 결론 | 이 자리에 무엇이 맞고 무엇이 안 맞는지 |
| B. 이 동네는 어떤 곳인가 | 누가 사나 · 일하나 · 지나가나 · 언제 붐비나 · 늘고 있나 · 상권 성격 (지금 자료로 가능) |
| C. 추천 Top 5 | 업종마다 아래 8칸 |
| D. 비추천 Top 5 | 이유 · 걸리는 지점(과밀/감소/고객층 불일치/공간 불가) · 다시 볼 조건 · 신뢰도 |
| E. 임대인 확인 목록 | 업종별 설비 질문을 하나로 모음 (예: "급배수 있나요? — 세탁·미용·음료") |
| F. 평가자 의견 | 구현됨. 의견 전부 + 지적마다 반영 여부 |
| G. 자료 한계 | 출처·기간, 없는 자료(매출·임대료·면적·규제)도 명시 |

**추천 업종 8칸 (C)**
1. 한 줄 이유
2. 주 고객층과 이 동네의 일치도 — 맞음 / 일부 / 안 맞음
3. 이용 시간대 적합성
4. 경쟁 — 50·200·500m 동종 점포 수, 가장 가까운 동종 점포 3곳 이름·거리
5. 버티는가 — 개폐업, 순증감, 교체율
6. 공간·설비 조건 — 급배수·전기·환기·층·면적
7. 위험과 "이 조건이면 해볼 만함"
8. 근거 신뢰도 — 높음 / 보통 / 낮음 + 이유

## 핵심 설계 두 가지
1. **숫자는 코드가, 해석은 모델이.** 모델은 숫자 칸에 원자료 경로만 고르고 값은 코드가 채웁니다.
   "숫자·단위 불일치로 근거가 버려지는" 문제가 구조적으로 없어집니다.
2. **업종 설명표(75개).** 업종마다 주 고객층 · 이용 시간대 · 필요 설비 · 층 선호를 표로 둡니다.
   모델 초안 → 사람 검수 → CSV → 생성 스크립트(지도 업종 설명표와 같은 방식).

## 영향
- `schemas.py`의 리포트 형식(DecisionResult)이 바뀝니다 → **PR 합의 필요**. 추가 방식이라 옛 결과도 읽힙니다.
- 판정관 지시문, 평가자 지시문, 목업, API 문서, 프론트 리포트(Top 3 → Top 5, 칸별 카드)가 함께 바뀝니다.
- 프론트가 리포트 화면을 만들기 **전에** 정해야 합니다.

## 정할 것
1. 구성·항목에서 빼거나 더할 것
2. 숫자를 코드가 채우는 방식으로 갈지 (추천: 예)
3. 업종 설명표를 만들지, 누가 검수할지
4. 자료가 없는 항목(매출·임대료)을 "확인 필요"로 노출할지
5. 평가자 지적이 어느 칸에 반영됐는지 표시할지
6. 화면: 업종 카드 펼침 / 업종 비교 표
