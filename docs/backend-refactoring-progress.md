## 실행 범위

- A1~A12 실행 승인. 최초 분석 3종은 그래프의 고정 병렬 실행을 유지한다.
- 유료 비교 실행은 최대 5회 승인으로 해석하며 현재 사용 1회. 오프라인 검증 뒤 실제 비교1회 완료.
- 커밋·푸시 승인 없음. 변경은 작업 트리에 유지하며 완료 단위와 검증을 이 문서에 기록한다.
- 사용자 작성 report-plan 두 파일은 수정하지 않는다.

## 사전 검사와 결정

- 기준: unittest 633개 통과, ruff check/format, mypy, catalog --check 통과.
- A1→A4: 실행 상태 타입은 execution/types로 옮기고 db/types는 기존 경로를 재노출한다.
- A2→A3: 하나의 registry가 동기/비동기 응답 경로의 슬롯과 작업을 함께 관리한다.
- A5→A6: 동기 저장 계약과 to_thread/_settle를 유지한다.
- A8→B1: 명백한 수치 오인만 수정하고 구조화 수치는 계약 변경 단계로 남긴다.
- A10→A11: 원자료 변경 시 색인을 다시 만들며 client 수명은 실행 범위로 한정한다.
- 결정: 현재 체크아웃에서 새 브랜치로 진행. 별도 worktree는 생성하지 않음.
- A1 결정: workflow는 ExecutionSettings도 서비스에서 가져오므로 설정 구현 역시 execution/settings로 이동. 클래스와 기존 import 경로는 유지하며, 설정을 공유하기 위해 추가 계층 역참조를 만들지 않음.

### 최종 리뷰

- executing-plans 스킬의 읽기 전용 별도 리뷰어 1명. Critical0, Important1, Minor1.
- Important: 호출 이력 항목/attempt 손상이 복원 검증을 통과해 모델 호출 후 실패할 수 있음. 회귀에서7가지 손상이 검증을 통과하는 RED 확인 후 객체·정수·양수·상한·중복 검사 추가. 서비스 재개도 생성기를 호출하지 않음 확인.
- Ruling: used와 calls 길이를 강제로 같게 만들지 않음 — 기존 호출 수만 있는 옛 상태(used>0, calls=[])를 유지하되 제공된 모든 항목의 번호는1..used 안에서 유일해야 함. 비용: 누락된 옛 호출 이력을 복원할 수 없음.
- Final: minor (deferred): p99·개별 DB 조회 시간은 미측정. 설계13장에 큐 시간·토큰·실제 모델/네트워크·배포 수용량도 미측정으로 명시. 후속 운영 측정에서 보완.
