# 초기 GET 수정 후 홍대 실테스트 — 2026-10-14

**초기404는 해소됐고 L직접 제출50개·G51개·C4여섯 개 관측까지 진행했다.**
평가자 병렬 단계에서 SQLite 저장 잠금 이후 진행이 멈춰 프로세스를 종료했다.
최종 결과·평가 완료·피드백은 미완료다. 추가 코드/프롬프트/상한 변경·재실행은 하지 않았다.

## 정체 원인과 남은 확인

확인된 실행 증거는 예산 저장의 OperationalError/녹화 STORAGE_FAILED와
DB/호출 기록의 진행 정체다. 네 평가자가 병렬 읽기를 시작한 뒤 발생했다.
오류 로그는 상세 SQLite 메시지 대신 안전한 예외 종류를 남겼다.
전역토큰/모델/시간 안전선 도달로 완료된 결과가 아니다.

별칭 생성의 코드상 경합 경로는 app/agentic/aliases.py:encode의while문이다.
두 연결이 같은fact_id의 별칭 없음 확인 후 동시에 INSERT OR IGNORE를 하면,
한쪽은 UNIQUE(request_id,fact_id) 충돌로 삽입이 무시될 수 있다.
현재는 별칭을 fact_id로 다시 조회하지 않고 counter만 늘려 같은 fact_id의
삽입을 계속한다. 이 경우 반복이 끝나지 않고쓰기트랜잭션을 붙잡을 수 있다.

이는 코드로 확인되는결함이며 이번 병렬 단계의 잠금 원인으로 유력하다.
실행 중 해당 스레드 스택을 채취하지 못했으므로 실제 잠금 소유자가 이 경로였는지는
직접 확정하지 않았다. 프로세스CPU시간230.61초가 관측됐고 별칭행57개 이후
모델/도구 저장이 더 진행하지 않았다. 수정·동시성 재현 시험은 이번에 하지 않는다.

초안의 숫자 문장 오류는같은제출에서 반복됐다. 평가 중customer의scorecard 요청과
examiner의fact 요청도 입력 규칙 오류를 한 번씩 냈다.
저장된 검토 의견이 없으므로 평가 지적·반영 여부는 산출할 수 없다.
