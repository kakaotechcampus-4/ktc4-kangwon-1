# 임대인 평가 입력·프롬프트 개선 및 두 지역 재검증

검증일: 2026-10-20

## 결론

임대인에게 기존 개폐업·수요·경쟁 자료를 먼저 제공하고 검토 우선순위를 명시한 뒤, 오금로와 항동을 각각 한 번씩 실제 분석했다. 두 지역 모두 공간 조건 외에 영업 지속성·임차 수요의 근거와 한계를 검토했고, 그 내용이 최종 보고서의 한계 또는 확인 조건에도 추가됐다.

확인한 것은 **검토 범위가 넓어졌다는 점**이다. 개별 임차인의 지급 능력이나 계약 지속성을 예측하는 기능을 만든 것은 아니며, 두 번의 실행만으로 품질 문제가 모두 해결됐다고 판단하지 않는다. 자료 인용의 의미 일치, 누락 자료 지적의 제출 가능성, 최종 보고서의 빈 설명 문제는 아래에 별도로 기록했다.

## 수정 목적과 역할 중첩에 대한 설계 의도

앱의 주 사용자는 임대인이므로, 임대인 평가자는 고객 수요·운영 조건·자료의 한계를 임대 결정과 연결해 함께 검토한다. 다른 세 평가자와 일부 항목이 겹치는 것을 허용하며, 같은 자료를 보더라도 공실 해소·임대 지속성·임대인 부담에 필요한 확인 사항을 제시하는 데 초점을 둔다.

이번 수정의 목적은 기존에 공간 초안과 시설 경고에 치우쳤던 임대인 검토에, 이미 수집한 개폐업·수요·경쟁 자료를 함께 제공하는 것이다. 자료 전달과 임대인 전용 지침을 보강해 임대인이 판단할 때 필요한 근거와 부족한 정보를 더 넓게 확인하도록 했다.

## 자료와 프롬프트를 함께 바꾼 이유

기존 입력은 초안에 이미 인용된 사실 위주라 공간 프로필과 임대인의 층·면적 답변이 중심이었다. 임대인이 다른 자료를 검토하려면 제한된 읽기 도구로 직접 찾아야 했다. 역할 지침에는 임대 지속성이 언급돼 있었지만, 어떤 자료를 어떤 순서로 읽고 어디까지 판단할지 설명이 짧았다.

새 입력은 상위 후보별로 다음 자료를 먼저 제공한다. 외부 자료를 새로 수집하지 않고, 같은 요청·스냅샷에 이미 저장된 사실을 사용한다.

| 검토 주제 | 제공하는 기존 자료 | 해석 범위 |
| --- | --- | --- |
| 영업 지속성 | 최근 연간 폐업률, 순변화율 등 개폐업 지표 | 업종 집단의 추세를 보는 간접 근거 |
| 수요 기반 | 유동·상주·직장 인구의 업종별 적합 지표 등 | 고객 수요에 관한 간접 근거이며 실제 임차 의향은 별도 확인 |
| 경쟁 환경 | 업종별 점포 수 등 | 출처의 기간·공간 범위 안에서 해석 |
| 공간 확인 | 현재 유효한 공간 비교와 임대인 답변 | 미검토 공간 초안의 한계를 유지 |
| 임대인 부담 | 임대료·공실 기간·공사비가 현재 입력에 없다는 진단 | 값을 추정하지 않고 확인 조건으로 남김 |

관측되고 인용 가능한 사실만 넣고, 값·단위·기간·공간 범위를 보존한다. 공간 범위는 중복을 제거해 별도 표로 제공한다. 미관측·미수집 여부는 진단으로 구분하며, 진단 건수를 실제 관측 수치처럼 인용하지 못하게 안내한다. 특정 후보가 입력을 독점하지 않도록 후보별로 교차 배치하고, 기존과 같은 12,000자 상한 안에서 구성한다.

임대인 전용 프롬프트는 영업 지속성 → 임차 수요 → 임대인 부담 → 공간 확인 순서를 명시한다. 집단의 개폐업 추세를 개별 임차인의 지급 능력·계약 유지 보장으로 확대하지 않도록 하고, 미확인을 수요 부재로 해석하거나 없는 임대수익을 추정하지 않도록 했다. 공간 경고는 유지하되 같은 경고의 반복보다 후보 판단에 필요한 확인 사항을 남기게 했다.

## 비교 조건과 방법

- 주소: 서울특별시 송파구 오금로 404, 서울특별시 구로구 연동로 191-19.
- 기존 공통 시험과 같은 반경 500m, 가상 답변은 1층·약 66㎡·주방/배기/급배수 있음.
- decision·평가자 모델은 기존 저비용 설정인 `openai/gpt-6-luna`. 두 실행 모두 자문 호출은 없었다.
- 최초의 오금로 다중 조건 시험 대신, 다른 지역과 조건을 맞춘 `ogeum-retest-20261020` 실행을 이전 기준으로 사용했다.
- 먼저 이전 DB를 복사하고 **동일 초안·동일 사실**로 입력 조립만 비교했다. 다른 세 평가자의 입력은 이전 실제 호출 기록과 일치했다.
- 이후 새 코드로 전체 분석을 주소별 한 번씩 실행했다. 두 지역 모두 이전과 공공 사실의 출처·지표·업종·기간·값·단위·상태·인용 가능 여부 및 최초 업종 점수가 같았다.
- 모델의 질문 선택은 고정하지 않았다. 항동은 설비 답변이 이전에는 `existing_facilities`, 이번에는 `space_condition`으로 저장됐다. 답변 내용은 같지만 전체 실행이 완전히 동일한 입력의 결정적 비교는 아니다.

### 기존 검사에서 처리한 오류와 남은 한계

1. **제출·조회 형식 오류는 남았다.** 오금로는 숫자를 문장에 쓴 지적이 거절된 뒤 수정됐다. 항동은 조회 지표를 한 번에 여덟 개 넘게 요청해 거절된 뒤 범위를 좁혔다. 최종 임대인 평가는 모두 완료됐지만 오류 없는 실행은 아니었다.
2. **항동의 임대료·공실 기간·공사비 누락 지적은 최종 제출에서 제외됐다.** 첫 제출에서 실제 fact 근거가 없어 기존 서버 검사가 거절했고, 재제출에서는 해당 지적을 뺐다. 다른 두 지적은 유지됐다. 이는 이번에 바꾸지 않기로 한 기존 인용·재제출 정책의 동작이다. 새 `missing_inputs` 진단 자체는 인용 가능한 fact가 아니다. 해당 항목을 정식 평가 근거로 삼으려면 실제 입력 수집 또는 누락 상태를 표현하는 계약의 별도 논의가 필요하다.
3. **출처별 한계를 섞어 설명하는 문제가 남았다.** 항동 임대인 지적은 로컬 `commercial_area.store_count` 사실들을 인용하면서 지도 검색에 해당하는 ‘첫 페이지 표본’ 한계를 함께 서술했다. 해당 점포 수에는 `local_fact_lineage`가 있다. 실제 인용 가능한 사실인지는 통과했지만, 문장 전체의 의미와 출처가 맞는지는 추가 검토가 필요하다. 최종 보고서에도 이 혼합 표현이 남았다.
4. **보고서의 빈 후보 설명도 확인됐다.** 항동의 `G202` 후보는 이유·위험·확인 조건 세 배열이 모두 비어 있다. 자동 계약 검사와 평가 의견 처리 완료 검사는 이를 오류로 잡지 않았다. 임대인 전용 입력 변경만으로 전체 보고서의 설명 완결성이 보장되지는 않는다.
5. **임대 사업성을 직접 계산할 자료는 여전히 부족하다.** 지역의 개폐업·고객 수요 자료는 보조 근거다. 실제 임대료, 임차인의 재무와 임차 의향, 공실 기간, 공사비 등을 확보하지 않았으므로 공실 해소 기간·월세 지급 확률·임대수익을 추정할 수 없다.
