# MVP2.0 진행 기록

기준 계획: `docs/mvp20-optimization-plan.md`
기준 커밋: `0c2ea3e`, 작업 브랜치: `feature/mvp-1.5-orchestra`

## 범위와 판단

- 기존 작업 위치 유지. 발표자료·프론트엔드 제외. 커밋·푸시하지 않음.
- PR별 검증 경계를 유지하며 우선 PR 1(1-1·1-2)을 진행한다.
- 폐업률은 계산식을 바꾸지 않고 **점포 수로 가중한 분기 평균 비율**로 설명한다. 기존 필드명은 호환을 위해 유지하고 계산 기준을 모델 입력과 결과에 제공한다. 연간 누적률로 읽지 않도록 한다.
- 2→3단계는 생성 문장 표시와 제거가 겹친다. 수치와 문장의 인용 가능 범위를 분리해야 한다.
- 4단계 공개 함수 삭제는 schemas.py 변경이 없어도 Python 호출자 호환성이 달라진다. API·validation_tool·예제를 함께 검증해야 한다.
- 5단계 공간 집합 통일은 동작 보존 리팩토링이 아니다. 폴리곤 포함·반경 교차의 목적을 합의하기 전 임의로 통일하지 않는다.
- 6-3 계약 변경과 7단계는 합의·실측 전 보류. 유료 실측은 승인 없이 실행하지 않는다.
- 계획은 별도 명세 없이 제공되었으므로 모호한 분석 정책은 구현 사실로 확정하지 않는다.

## PR 2

- 인구 API의 빈 선택 항목을 `None`으로 정리하고 JSON·필드 변환 실패를 `UPSTREAM_ERROR`로 수집한다.
- 상권 디코딩·리다이렉트 실패를 해당 에이전트 오류로 반환한다. 캐시 폴더 생성 실패와 비 UTF-8 손상 캐시는 분석 실패로 전파하지 않는다.
- 개폐업 환경변수 오류는 `CONFIG_ERROR`, 원본 숫자 오류는 `UPSTREAM_ERROR`로 구분했다. 자료 없음은 예외 메시지 대신 전용 예외로 판단한다.
- 상권·브랜드 API를 HTTPS로 변경했다. 키 없는 요청으로 두 엔드포인트의 TLS 연결과 `SERVICE_KEY_IS_NULL` 응답을 확인했다. 인증된 실제 조회 검증은 아니다.
- 채점 가능한 업종이 1개면 상대 점수를 보류하고 `confidence="low"`로 반환한다. 원본 관측값은 보존하며 결과는 `partial`이다. 점포 5개 미만의 기존 신뢰도 강등은 유지한다. 2개 이상에 대한 추가 표본 기준은 임의로 만들지 않았다.

- 변경 전 오류 재현 후 수정. 최종 backend 482개·validation_tool 29개 통과, Ruff·포맷(163개 파일)·mypy(80개 소스) 통과.

- 읽기 전용 리뷰에서 차단 회귀 없음. 추가로 지적된 손상 캐시 디코딩 처리를 테스트와 함께 보완했다.
- 잔여 경계: 인구 원본의 빈 코드·명칭 `None`·비유한 숫자 검증은 별도 보강 필요. 모든 외부 자료 오류를 완전히 처리했다고 보지 않는다.
- 발표자료·프론트엔드·공통 스키마 수정, 실제 LLM 호출, 커밋·푸시는 하지 않았다.

## PR 3 — 근거 정책, 첫 묶음

- `index_paths()`가 `citable=false` 하위 트리와 이를 포함한 상위 객체의 인용을 차단한다. 업종별 경로 목록·교정 후보·최종 검증이 같은 규칙을 사용한다. 허용된 형제 값과 실제 숫자 0은 유지한다.
- Ruling: 기존 문자열·배열을 객체로 감싸지 않고 `citable: {필드명: false}`도 지원한다. 출력 필드 자료형을 유지하기 위한 선택이며 소비자는 이 메타데이터를 무시할 수 있다. 규칙은 프롬프트와 인덱서에 함께 명시한다.
- 개폐업의 생성 `type`·`evidence`, 상권의 생성 `summary`·`summary_text`를 직접 근거에서 제외했다. 원본 출력은 보존한다.
- Ruling: 음식점 전체 밀도는 개별 업종에 귀속시킬 수 없으므로 직접 인용에서 제외한다. 참고 데이터는 보존하지만 음식점 업종에도 해당 지표 경로를 직접 인용할 수 없다는 제한이 있다.
- 소표본 LQ는 기존 `min_count_for_specialization` 기준(기본 5개)을 적용한다. 기본 분석과 주변 비교 보완 모두 수치는 보존하되 인용을 차단한다. 0개 업종은 순위 목록에서 제외하고 전체 업종별 건수에는 남긴다.
- 미완료: 개폐업 분기 보완의 원본 합계·신뢰도 검증, 인구 기간·지표 명칭, 지도 검색 분류 필터, 전체 에이전트 인용 경로 샘플 검증. 2단계 전체 완료로 보지 않는다.
- 검증: 실패 재현 후 수정, backend 489개·validation_tool 29개 통과. Ruff·포맷 163개·mypy 80개 통과. 독립 읽기 전용 리뷰에서 차단 이슈 없음.
- 후속 테스트 보강: 최소 점포 수와 정확히 같은 경계의 기본·보완 LQ 허용, 소표본 `lq_district` 차단을 직접 확인하는 테스트.
- Ruling: 이전 저장 결과에는 `citable` 표시를 소급 추가하지 않는다. 이번 변경은 새 분석 결과 대상이며, 과거 결과를 재사용하면 새 인용 정책이 일부 적용되지 않는 한계가 있다. 저장 결과 이전은 별도 작업이다.
- 실제 API·LLM 검증은 하지 않았으며 커밋·푸시·발표자료 수정도 하지 않았다.

## PR 3 — 보완 검증·인구 설명·지도 필터

- 개폐업 보완 업종에 최초 신뢰도를 전달한다. 원본 기간별 개·폐업 합계, 순증감, 최근 4분기 건수, 최신·평균 점포 수와 비교하고 분기 폐업률도 재계산해 불일치 시 채택하지 않는다. 결측을 0으로 바꾸지 않는다.
- 최초 자료에 비교할 개·폐업 합계가 없으면 검증 불가로 보완 채택을 거절한다. validation_tool의 가상 종합·보완 자료도 같은 계약으로 맞췄다.
- 주거·직장 인구의 실제 기준 분기와 기간 차이 경고는 이미 구현돼 있었다. 기존 인구 테스트 37개로 확인했으며 중복 구현하지 않았다. 전체 상권 합산 통행량과 면적 안분 추정 통행량은 기존 키·계산을 유지하고 단위 설명을 구분했다.
- Ruling: 지도 분류 필터는 대응이 확실한 I212→CE7, 나머지 음식점 대분류 I2→FD6만 적용한다. 다른 업종에 추정 매핑을 넣지 않는다. 해당 업종의 상호명 오탐은 여전히 남을 수 있다. 필터는 키워드 조회의 조건이며 공통 계약의 시설 조회 category_code는 변경하지 않는다.
- 읽기 전용 리뷰에서 차단 이슈 없음. 보강 대상: 5개 이상 분기에서 최근 4분기 합계만 비교하는 독립 경계 테스트.
- 전체 에이전트의 인용 경로 샘플 고정 검증과 앞서 기록한 경계 테스트는 아직 남아 있다. 실제 API·LLM 호출, 발표자료 수정, 커밋·푸시는 하지 않았다.
- 최종 검증: backend 491개·validation_tool 29개 통과, Ruff·포맷 163개·mypy 80개 통과. validation_tool 최초 검사에서 이전 대역 계약의 누락으로 2건 실패했으며 종합 지표·신뢰도와 지도 검색 인자 호환을 수정한 뒤 재검증했다.
- `validation_tool/run.py`는 현재 Git 제외 대상이다. 로컬 수정은 완료했지만 일반 Git 커밋에는 포함되지 않는다. 제외 규칙은 변경하지 않았다.

## PR 3 마무리·PR 4 시작

- 실제 상권 분석·보완 결과에서 최소 점포 수 5개일 때 LQ 인용이 유지되는지, 소표본 LQ·지역 LQ 차단 여부를 보강했다. 5분기 자료에서 최근 4분기 합계만 비교하는 회귀 테스트를 추가했다.
- 세 분석 자료의 축소 샘플에 대해 허용 인용 경로·업종 소유를 고정 검사한다. 운영 데이터 전체 스냅샷이나 실제 모델 품질 평가는 아니다. 이번 테스트는 기존 동작을 보호하는 특성 테스트로 먼저 통과했다.
- 개폐업 기본 파이프라인의 배치 LLM 호출을 제거했다. 데이터 API → 전처리 → 기존 점수 계산 → 건수 설명 → 공통 응답 순서다. API 응답만 대역으로 주입하고 모델 호출을 금지한 통합 테스트가 변경 전 실패하고 변경 후 통과했다.
- Ruling: 유형은 기간 내 개업·폐업 건수 비교로 `개업 우위`, `폐업 우위`, `개폐업 균형`을 사용한다. 새 성장·안정성 임계값을 만들지 않기 위한 선택이며 기존 LLM 유형 문구와는 달라진다. 점수·수치·신뢰도·출력 자료형은 유지한다.
- 기존 `llm.py`와 `llm_settings` 인자는 호출자 이관 전까지 보존한다. 직접 이전 함수를 호출하면 여전히 모델 호출이 가능하므로 전체 코드에서 LLM이 제거됐다고 표현하지 않는다. 상권·인구 내부 모델 제거와 관련 파일·설정 정리는 다음 묶음이다.
- backend 494개·validation_tool 29개 통과. 실제 외부 API·LLM 호출, 커밋·푸시, 발표자료 수정은 하지 않았다.
- Ruff·포맷(163개)·mypy(80개) 통과. 독립 읽기 전용 리뷰에서 차단 이슈 없음. 이전 LLM 모듈의 import 시 프롬프트 파일 읽기는 후속 정리 전까지 남아 있다.

## PR 4 — 상권 요약·인구 선별 기본 호출 제거

- 상권 요약 모델 호출 대신 조회 반경·점포 수로 기존 `summary`·`summary_text`를 채운다. 수치·출력 구조와 직접 인용 차단은 유지한다.
- 인구 기본 선별은 비어 있지 않은 상권·반경 자료와 2개 이상 분기의 추세를 유지한다. 비중과 중복되는 원값은 최종판단 입력에서 제외하며 저장 원본 수치는 보존한다. 반경 자료의 실제 0은 제외 조건이 아니다.
- 등록부와 API 목업 예제에서 인구 선별 모델 주입을 제거했다. 모델 호출 금지 테스트와 실제 계산 경로로 확인했다. 최종판단·오케스트레이터 모델은 변경하지 않았다.
- 남은 작업: 이전 모델 모듈·설정·직접 호출 테스트 정리, 주입 선별 함수의 넓은 예외 처리와 저장본 `interpretation` 필터 이관, 지도 매핑 재사용. 따라서 3단계 전체 완료는 아니다.
- 검증: backend 495개·validation_tool 29개 통과. backend Ruff·포맷 163개·mypy 80개 통과. 2분기 추세 포함 검사를 추가한 API 목업 테스트 4개도 통과했다.

## 2026-09-29 — 4·5단계 마무리

### 4단계: 실행·저장 경로 정리

- 서비스 → `run_graph()` 직접 호출로 통일했다. `run_react`, `run_analysis`, `resume_graph`, 호환용 `app/orchestrator.py`, 오케스트레이터 모델·프롬프트·도구 선택 인자를 제거했다.
- 저장 콜백 6개는 `RunHooks`로 묶었다. 고정 순서 이후 보완·지도·선택 질문은 유지한다.
- 질문 재개·판단 재시도는 `repository.load_resume_context()`의 복원 로직을 공유하고 `decision.evaluate()`를 직접 호출한다. 기존 분석을 다시 조회하지 않는다.
- 실패 코드·기록을 공통화하고 evaluate의 한계 수집·입력 조립·출력 분기를 분리했다.
- 독립 검수에서 재시도 중 시간 초과·취소가 다음 재시도를 막는 회귀를 발견했다. 재시도 실패 코드를 기존대로 보존하고 실패 재현 → 수정 → 재시도 성공을 검증했다.
- Ruling: 서비스 검증을 모으되 독립 주소 준비 함수의 입력 검증과 분석 결과의 계약 검증은 삭제하지 않았다. 신뢰 경계가 달라 필요한 검증이다.

### 5단계: 공용화·미사용 코드 정리

- `app/seoul.py`에서 비동기 HTTP 전송·본문 검증·이전 분기 계산을 공유한다. 개폐업 urllib 호출을 없애고 실제 파이프라인을 async로 연결했다. SHP 파일 읽기와 동기 대역 함수는 스레드에서 실행한다.
- 개폐업은 요청 안에서 연결·분기 탐색 페이지를 재사용한다. 요청이 끝나면 캐시를 버리고 반환 자료는 복사한다. 인구 최신 분기 탐색도 같은 클라이언트 안에서 재사용한다.
- 공용화 중 달라졌던 인구 시간 초과 코드를 `UPSTREAM_TIMEOUT`으로 복원했다. 실제 HTTP 대역에서 코드 보존을 검사했다.
- 인구 전량 수집·재시도 설정을 `scripts/fetch_population_snapshot.py`로 옮겼다. 미사용 반경 환경변수·개폐업 중심점 거리 설정·상권 오류 상수 등을 제거했다.
- 지도는 `observe()` 하나로 연결한다. 옛 `search()`·결과 스키마·보조 함수를 제거하고 단독 예제·테스트도 이관했다.
- Ruling: 시설 별칭은 예제에서 명시적 시설 코드로 변환한다. 키워드 문자열이 다르다는 이유로 원본 장소를 삭제하지 않는다. 원본 분류 보존 → 실제 75개 업종 매핑 → 업종별 표본 집계가 현 계약이며 전체 검색 건수를 매칭 비율로 보정하지 않는다.
- 상권의 중복 표현 `same_type_count`·`marshallian`·`density_sq`·`restaurant_density.squared`를 제거했다. 건수·밀도·다른 계산 지표는 유지한다. 과거 저장 JSON은 변경하지 않았다.
- 상권 HTTP 슬롯은 서버 워커의 단일 이벤트 루프에서 공유한다. 첫 페이지·재시도도 같은 한도를 사용하고 대기·실패·취소 때 슬롯을 반환한다. 두 클라이언트 동시 요청이 설정 상한을 넘던 실패를 재현하고 수정했다.
- Ruling: 워커는 최초 `SBIZ_MAX_CONCURRENCY`를 유지한다. 다중 워커·다중 이벤트 루프를 합친 전역 쿼터 조정은 하지 않는다. 현재 단일 루프 서버를 넘어 배포할 때 별도 조정이 필요하다.
- 합의한 분석 범위는 바꾸지 않았다. 개폐업 포함 폴리곤, 인구·상권 기존 반경, SHP 캐시·공통 좌표 계산을 유지한다.

### 검증·범위

- Python 3.12.14: 백엔드 **474개**, 로컬 validation_tool **29개** 통과.
- 백엔드 Ruff·포맷 **158개**·mypy **77개** 통과. 업종표 CSV와 catalog 동기화 검사 통과.
- 외부 HTTP를 금지한 기존 목업 예제: 최종 `ok`, DB `completed`, 분석 3개·최종판단 1개 저장 확인.
- validation trace에서 `orchestration_model` 없음, 보완 실행·채택·재판단과 지도·질문·답변 재개를 확인했다.
- 제거한 기능 전용 테스트는 없애고 서비스·그래프·관측 계약 테스트로 옮겼다. 이전 테스트 개수 유지 자체를 완료 기준으로 삼지 않았다.
- 이번 마무리에서는 실제 API·LLM을 다시 호출하지 않았다. 위 실측 표는 앞선 고정 엣지 전환 당시 기록이며 이번 비동기 이관의 속도 측정값은 아니다.
- 7단계 추가 LLM 미도입 결정은 유지한다. 발표자료·프론트엔드·운영 데이터·키는 변경하지 않았다.
- 삭제 파일은 Git 이력에서 복구 가능하다. 커밋·푸시는 하지 않았다. `validation_tool/`은 계속 Git 제외 상태다.

### 판단·남은 한계

- 지도 일부 매핑 실패는 기존 `partial` 처리를 유지하고 안내만 보강했다. 미확정 자료는 집계하지 않아 과소 집계 가능성이 있으므로 경고를 함께 읽어야 한다.
- 정상 선별 경고만 제거했다. 실제 자료 부족·공간 차이를 숨겨 `ok`로 만드는 변경은 하지 않았다.

- 단회 실측과 회귀 테스트는 추천 타당성 평가를 대신하지 않는다. 업종 매핑 사람 검수·추천 품질 평가·부하 시험은 별도 작업이다.
- 공통 스키마·분석 범위·프론트·발표자료는 이번 수정에서 변경하지 않았다. 설계 결정 기록의 ADR-03·04·07·09·10·11·12를 갱신했다. 커밋·푸시는 하지 않았다.
