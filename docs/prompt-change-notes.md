# B6 프롬프트 변경 이유

## Founder 전용 보완 (2026-10-19)

- [Founder 평가표 v0.1](founder-evaluator-rubric.md)에 공간·운영, 설비·공사·초기 준비, 영업 지속성, 경쟁 속 실행 전제, 입점 전 직접 확인 순서의 다섯 항목을 고정했다. 별도 점수·순위는 만들지 않는다.
- 변경은 PERSONAS["founder"]에 한정한다. 운영 충돌·설비 전제를 우선하고, 확인 대상·행동·순서를 남기도록 했다. COMMON·다른 세 persona·패킷·계약·예산은 바꾸지 않는다.
- 패킷에 없는 초안 문장 단정·누락을 추측해 지적하지 않고 condition/action_condition만 제출하도록 했다. 초안 본문 전달은 후속 과제다.
- 공간 요건은 Top5 중 관련 업종의 industry_code를 지정하고 일반 조회 limit≤32로 좁힌다. 기존 실행에서 두 번 거절된 limit=51 일반 조회와 같은 오류 반복을 피하도록 했다. 다섯 업종 전부를 각각 조회하라는 뜻은 아니다.
- 관측·인용 가능한 근거만 지적에 사용한다. 초안의 확정 요건화, 소매의 주방·조리 배기 부재에 대한 불리 판단, 비용·손익 추정은 금지한다.
- 빈 issues는 조회 실패·근거 부족이면 conditional, 필요한 자료를 읽고 중요한 모순·확인 과제가 없으면 agree다. 관측된 핵심 운영 불가 외에는 oppose를 사용하지 않는다.
- 판정 기준과 이전 founder의 거절·중복·반영·토큰·시간은 전용 평가표에 기록했다. 단위 테스트는 모델 품질을 증명하지 않으며, 실제 모델 비교는 별도 승인 뒤 한 번의 관찰로 보고한다.

## 이전 B6 기록

- 상위 열 업종을 하나씩 검토하고 `unknown` 이유를 남기도록 했다. 근거가 부족한 업종이 검토 과정에서 조용히 빠지는 일을 줄인다.
- 코드 점수 조회는 초기 후보를 한 묶음으로 한 번 수행하고 결과를 재사용한다. 사실 조회는 업종·출처·지표 또는 이미 받은 ID로 좁혀 중복 조회를 줄인다.
- 공간 요건은 `industry_profile`의 `space_requirements` 사실로 읽되 `reviewed=false`인 운영 가설로 취급한다. 임대인이 확인한 조건과 대조해 확인 항목으로 남기며 법규나 L 가감점 근거로 쓰지 않는다.
- 소매업의 주방·조리 배기 부재, 예약·기업 거래 업종의 층·보행 조건을 획일적인 불리 요인으로 삼지 않도록 했다.
- 미확인 핵심 임대 조건은 처음에 최대 세 항목을 한 번 묶어 묻는다. 자료로 확인 가능한 조건이나 이미 받은 답변을 다시 묻지 않는다.
- 기존 사실로 판단하기 어려운 조건에만 추가 조회를 사용하고, 해석 충돌·결측이 후보나 확인 조건을 바꿀 때 자문한다.
- 자유 문장의 숫자는 사실 ID와 슬롯으로 인용한다. 평가자는 읽기 세 번과 제출 한 번 안에서 확인한 사실과 실행 전 확인 조건을 남긴다.

코드 채점, 도구 입력 계약, 예산 상한은 이번 문장 보완으로 변경하지 않는다.

공간 요건 CSV는 51행이며 모든 행이 confidence=low, reviewed=false이다.
등록 원문·fact는 추적 가능한 초안이지만 NEW_METRICS에 포함하지 않는다.
확인된 임대인 답변·지도 등 새 사실을 L의 근거로 쓰고, 초안 자체는 가감점하지 않는다.
실행·계약·파일 이동과 나눌 수 없는 프롬프트 문장은 앞선 묶음·리팩토링 커밋에 포함했다.
전체 430개 회귀 및 408건 코드 점수 동일성을 확인했으며 실제 모델 품질은 승인된 한 실행에서 관찰한다.
