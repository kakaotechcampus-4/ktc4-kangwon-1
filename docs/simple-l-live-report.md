### 원인

`api/v1/jobs.py:start_job`은 백그라운드 작업을 등록하고 즉시202를 반환한다.
events는 DB 요청 행 생성 전이라도 작업 목록에 ID가 있으면 pending을 반환한다.
반면 `api/v1/analyses.py:get_analysis`는 DB의 요청 행만 읽고 아직 없으면404를 반환한다.
즉, **202/events pending 이후 요청 행이 만들어지기 전에 GET이 들어갈 수 있다.**

측정 스크립트가 이 초기404를 대기 상태로 처리하지 않고 raise_for_status로 종료했다.
finally에서 서버를 닫으면서 진행 중 요청이 취소됐다. 이후 DB에는 CancelledError가
조회·채점 단계로 기록됐다. 모델/채점/L 검증이 실패해서 멈춘 결과가 아니다.
이 초기 조회 경합은 기존 목업 회귀에서 드러나지 않았다.
이번 작업에서는 원인만 기록하고 공개 API·측정 스크립트 수정/재시도는 하지 않는다.
