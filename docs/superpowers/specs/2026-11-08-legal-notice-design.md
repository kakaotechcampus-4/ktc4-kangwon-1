# 법적 안내 설계 — 개인정보 처리방침·이용약관·가입 동의

작성 2026-11-08. 실험소 사본(`ktc4-kangwon-1-lab`, develop 11a0cde 기준)에서 만든다.

## 1. 왜 하는가

- 팀은 이 서비스를 대회 뒤에도 실제로 운영할 생각이다. 사업자 등록은 아직 없다.
- 사업자가 아니어도 업무로 회원 정보를 다루면 개인정보 보호법의 "개인정보처리자"다(제2조 제5호: "공공기관, 법인, 단체 및 개인 등"). 그래서 지금도 다음이 의무다.
  - 개인정보 처리방침을 정해 홈페이지에 계속 게재(법 제30조, 시행령 제31조 제2항). 어기면 1천만원 이하 과태료(제75조 제4항 제8호).
  - 개인정보 보호책임자 지정(제31조 제1항). 어기면 3천만원 이하 과태료(제75조 제2항 제14호의2, 법률 제21445호).
- 서비스 완성도 네 묶음(법적 안내 → 계정 → 사용 흐름 마감 → 결제) 중 첫 번째다. 결제가 약관·환불 규정에 기대므로 먼저 한다.

## 2. 목표

1. 개인정보 처리방침 페이지 `/privacy`
2. 이용약관 페이지 `/terms` (무료 시범 운영 기준)
3. 이메일 가입 화면
   - 필수 체크 1개: "만 14세 이상이며 이용약관에 동의합니다"
   - 처리방침은 체크 없이 링크로 안내
   - 이름 입력 칸을 뺀다
4. 카카오로 시작하는 버튼 아래 안내 문구: 계속하면 만 14세 이상이며 이용약관에 동의하고 처리방침을 확인한 것으로 본다
5. 약관 동의 기록을 서버에 남긴다(새 표)
6. 카카오 프로필 사진 주소를 더는 저장하지 않는다
7. 주인 없는 옛 분석 기록(2026-10-27 이전)을 아무도 열 수 없게 막는다
8. 바닥글에 약관·처리방침 링크와 "사업자 등록 전 시범 운영" 표시
9. 분석 중 질문의 상세 답 칸에 "이름·연락처 같은 개인정보는 적지 마세요" 안내
10. 운영자용 스크립트: 요청 하나에서 사용자가 직접 쓴 답 글을 요청 DB 어디에도 남지 않게 지운다(화면 없음)

## 3. 하지 않는 것

- 결제·환불 조항 — 결제 단계에서 약관에 더한다
- 계정 설정 화면(이름 입력·비밀번호 변경·탈퇴 버튼) — 다음 묶음. 그전까지 권리 행사와 탈퇴는 처리방침의 메일로 받는다
- 메일 알림, 운영자 기능
- 기존 가입자에게 다시 동의받기 — 법적 의무가 아니다(제30조 제2항은 "쉽게 확인할 수 있도록 공개"). 새 가입자부터 동의를 받는다
- 마케팅 수신 동의, 만 14세 미만 법정대리인 동의 절차
- 서버 nginx 설정, 도메인 메일(DNS) 설정, 카카오 개발자 콘솔 설정 — 저장소 밖의 일
- develop 반영과 운영 배포 — 실험소에서 끝내고, 옮길지는 나중에 따로 정한다. 다만 옮길 때 안전하도록 되돌리기 대비(9절 외래키)는 미리 넣는다

## 4. 실패로 보는 것

- 처리방침에 코드와 다른 사실이 적힌다(아래 6절 근거와 하나라도 어긋나면 실패)
- 가입·로그인 흐름이 깨지거나 E2E가 실패한다(E2E는 로그인 라벨 '이메일'·'비밀번호'에 기대고, 4xx·console.error가 나면 실패)
- 새 라이브러리를 들이거나 계층 규칙·저장 창구 1:1 규칙을 어긴다
- 페이지가 법률 자문을 받은 확정본처럼 보인다 — 출시 전 법률 검토 대상임을 문서 머리에 밝힌다

## 7. 처리방침 골격

법 제30조 제1항과 시행령 제31조 제1항의 항목 순서를 따른다. 각 항목 내용은 6절 사실에서만 가져온다.

1. 처리 목적 — 회원 관리, 상가 분석 리포트 제공, 부정 로그인 방지
2. 처리 항목과 법적 근거 — 필수(계약 이행, 제15조 제1항 제4호)와 그 밖의 근거를 표로 구분한다(제22조 제3항). 로그인 시도 기록의 근거는 법률 검토 표시
3. 보유 기간 — 6절 그대로(계정: 탈퇴 즉시 삭제, 로그인 시도: 15분 뒤 정리, 세션 14일, 분석 기록: 운영 기간 보관·탈퇴 시 익명화, 질문 답 글: 요청하면 지움, 서버 접속 기록: 확인 중). 이미 AI 제공자에게 전달된 내용은 그 회사의 보관 정책을 따른다는 점을 확인해 적는다
4. 파기 절차·방법 — DB 행 삭제
5. 처리 위탁 — AWS(서버·DB), Vercel(화면 제공), Resend(메일), 엘리스(AI 분석 중계), 카카오(로그인·주소·지도)
6. 국외 이전 — Vercel·Resend·OpenAI(미국). 제28조의8 제2항 다섯 가지(항목, 나라·시기·방법, 받는 자 이름·연락처, 목적·보유 기간, 거부 방법·결과)를 표로. 받는 자 연락처와 각 회사의 보유 기간은 각 회사 공개 문서로 확인해 적고, 확인 못 하면 "확인 중"으로 둔다
7. 안전성 확보 조치 — 비밀번호 scrypt 해시, 세션·메일 토큰 해시, HTTPS, 서버 접근 제한(SSM·IAM 역할)
8. 정보주체 권리와 행사 방법 — 열람·정정·삭제·처리정지를 메일로. 질문 답 글은 계정 주인임을 확인한 뒤 스크립트로 지운다. 카카오 연결 해제는 카카오 계정 설정에서
9. 자동 수집 장치 — `chaeum_session` 쿠키(로그인 유지 14일, 거부하면 로그인 불가), sessionStorage, 서버 접속 기록
10. 만 14세 미만 — 가입을 받지 않는다
11. 보호책임자 — 최용빈, `privacy@chaeum-ai.kr`
12. 시행일·변경 — 시행일 표기, 바꾸면 이 페이지에 게시

## 8. 이용약관 골격

목적 · 정의 · 약관 게시와 변경 · 가입(만 14세 이상, 이메일 확인) · 서비스 내용(무료 시범 운영, 리포트는 참고용이며 성공·매출을 보장하지 않음 — `backend/README.md` "추천 점수는 성공 확률·매출·수익 예측이 아닙니다") · 이용자 의무(남의 주소·정보 입력 금지, 질문 답에 개인정보 쓰지 않기) · 서비스 변경·중단 · 책임 제한 · 탈퇴 · 분쟁. 결제 조항 자리는 비워 두지 않고 "유료 서비스는 시작 전에 이 약관을 고쳐 알린다"로 쓴다.

## 9. 만드는 방법 (정해진 것)

코드 규칙은 `AGENTS.md`, `docs/CONVENTIONS.md`, `docs/TESTING.md`를 따르고, 코드에서 확인한 관례 중 이번 일에 걸리는 것은 다음과 같다.

- 사용자 규칙: **새 주석을 넣지 않는다**(기존 주석은 유지), 새 라이브러리 금지, 커밋에 도구 흔적 금지, `backend/.env` 열지 않음.
- 서버 흐름: `api/v1/auth.py` → `application/services.py`의 `AuthService` → `application/auth.py` 유스케이스 → `storage().users`를 `asyncio.to_thread`로. 오류는 `AuthError("대문자_코드", "한국어 문장")`, HTTP 번호는 API가 정한다. 요청 본문은 `<무엇>Body` + `extra="forbid"`.
- 새 저장 함수는 `repository/*.py`와 `application/ports/storage.py`의 창구 정의가 이름·인자 1:1(`tests/test_storage_port.py`), 내부 헬퍼는 `_` 접두. SQL은 infrastructure 밖에 두지 않는다.
- DB 판 올리기는 표·인덱스 "추가만"(`connection.py`), 선례 commit 242e166.
- 시험: unittest, 임시 DB + `create_app(settings=..., load_env=False)` + `TestClient(base_url="https://testserver")`, 쓰기 요청에 Origin 헤더.
- 화면: 랜딩 빼고 페이지는 `'use client'`인데 metadata가 필요한 정적 페이지는 서버 컴포넌트로. Footer는 레이아웃이, Header는 페이지가 그린다. 색은 `styles/tokens`, 글자 크기는 `text-13/15/17` 스케일. 계정·법적 화면은 합니다체, 분석 화면은 해요체. 실패 문구 "…하지 못했습니다. 잠시 후 다시 시도해 주세요." 화면 시험은 Vitest(`.test.tsx`=jsdom).

### 서버
- 새 표 `terms_agreements` — `user_id`(users 참조), `terms_version`, `method`(`email`·`kakao` CHECK), `agreed_at`. 기본키 `(user_id, terms_version)`.
  - `SCHEMA_VERSION` 6→7, `_UPGRADABLE_FROM` `{5, 6}`, `tests/test_db_migration.py`에 v6 파일이 v7로 올라가는 시험, `docs/DATABASE.md` 갱신(선례 commit 242e166).
  - `user_id` 외래키는 `ON DELETE CASCADE`로 둔다. 외래키가 켜져 있어, 이렇게 해야 지금의 `delete_user`도, 나중에 옛 릴리스로 되돌린 코드도 탈퇴에 실패하지 않는다.
- 약관 판 상수는 domain에 둔다(순수 값).
- 이메일 가입: 요청 본문에 `agree_terms`(참이어야 함). 아니면 `AuthError("TERMS_REQUIRED", "이용약관에 동의해야 가입할 수 있습니다.")` → API가 422. 계정 생성과 동의 기록은 한 트랜잭션. 가입 요청에서 `display_name`을 뺀다(이름은 다음 묶음의 계정 설정에서 넣는다). 이미 저장된 이름은 그대로 둔다.
- 카카오: 새 계정을 만들 때만 같은 트랜잭션에서 동의 기록(`kakao`). 프로필 사진 주소는 읽지도 저장하지도 않는다. 기존 카카오 계정이 로그인하면 남아 있던 사진 주소를 지운다.
- `/auth/me` 응답에서 `profile_image_url`을 뺀다(화면이 쓰지 않음). `docs/API_CONTRACT.md` 갱신.
- 옛 분석: 소유자 없는 요청은 주인과 무관하게 열람 불가(404). `LEGACY_OWNER_CUTOFF`와 그 분기를 없애고 시험·`docs/DATABASE.md`를 고친다.
- 질문 답 지우기 스크립트(`backend/scripts/` 아래, 화면 없음)
  - 입력: 요청 번호. 계정 주인 확인은 운영자가 메일로 받은 요청과 대조해 사람이 한다.
  - 결과: 그 요청에서 사용자가 직접 쓴 답 글(질문의 상세 답·자유 입력)을 요청 DB의 모든 표에서 지움 표시(예: `[삭제됨]`)로 바꾼다. 답이 들어가는 곳은 `facts`만이 아니라 질문 기록·실행 기록(AI 대화)·결과 등 여러 곳일 수 있으니, 계획 단계에서 전부 찾아 목록으로 만든다. 고르기만 한 선택지 값은 남겨도 된다. 선택지와 자유 글을 가를 수 없으면 그 요청의 답 값을 모두 지운다.
  - 지우기 금지 장치는 그 작업 한 트랜잭션 안에서만 잠시 풀고 다시 건다. 중간에 실패하면 모두 되돌린다.
  - SQL은 infrastructure에 두고 스크립트는 창구로 부른다.
  - 시험: 스크립트를 돌린 뒤 요청 DB 전체 글에서 원래 답 글이 0건이고, 지우기 금지 장치가 다시 걸려 있으며, 같은 요청 조회 API가 여전히 열린다.
