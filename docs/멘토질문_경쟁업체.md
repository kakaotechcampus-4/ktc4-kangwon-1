# 멘토 질문 — 경쟁업체 분석 에이전트

최용빈(BE) · 2026-09-16

전부 실제로 막혔던 지점이고 숫자는 실측입니다. 우선순위 순으로 정리했습니다.

## 1. 결정 에이전트가 빈 객체 `{}`를 냅니다 🔴

상권 분석 결과를 결정 에이전트(LLM)에 넘기면 응답이 `{}` 두 글자로 옵니다.

| 입력 | 프롬프트 토큰 | 응답 |
| --- | --- | --- |
| 상권 분석 전량 | 32,585 | `{}` |
| 상권 분석 전량 (재시도) | 40,153 | `{}` |
| `by_radius` 블록 제외 | 7,479 | 정상 (3,168자) |

`finish_reason`은 `stop`입니다. 잘린 게 아니라 모델이 스스로 빈 객체를 내고 끝냅니다. 두 번 다 같았습니다.

원인을 보니 결정 에이전트가 요청 전체를 한 줄로 프롬프트에 넣고, 자르거나 요약하는 코드는 저장소 어디에도 없습니다(`decision/agent.py:51`). 그래서 저희가 `digest`를 따로 내든 필요한 필드만 읽게 하든 효과가 없고, `data` 자체를 줄여야만 반영됩니다.

반경 단계 5개→3개, 순위 배열 10→5로 줄여 `data`를 52,882자→36,925자(−30%)로 줄이니 정상 응답(추천 5건·근거 12건)이 왔습니다.

**질문**
1. 빈 객체가 오는 게 토큰 길이 문제가 맞을까요? `stop`이라 길이 초과는 아닌 것 같은데, 긴 입력에서 모델이 조용히 포기하는 알려진 현상인지, JSON 모드+긴 입력 조합 같은 다른 원인을 봐야 하는지 궁금합니다.
2. 분석 에이전트가 소비자의 토큰 제약을 알아서 맞추는 구조가 맞을까요? 지금은 `by_radius`를 줄여 결정 에이전트를 살렸는데, 그러면 리포트가 쓸 차트 재료도 같이 줄어듭니다. 소비자가 결정·리포트 둘인데 같은 객체를 받는 구조라 경계를 어디에 둬야 할지 여쭤봅니다.
3. 빈 응답 감지 후 재시도하는 표준 패턴이 있을까요? 지금은 저희 요약 LLM만 2회 재시도를 겁니다.
4. 한 프롬프트에 세 에이전트 결과를 다 넣는 구조 자체가 맞을까요, 업종을 단계적으로 좁히는(후보 5개→상세) 방식이 나을까요?

## 2. 서로 다른 공공데이터 분류체계를 잇는 정석이 궁금합니다 🔴

저희는 소상공인 중분류 75종(`I201`), 개폐업 파트는 서울시 생활밀접업종 100종(`CS100001`)을 쓰는데 두 체계에 공통 코드가 하나도 없습니다.

이름 유사도로 먼저 매핑해봤더니 못 쓸 수준이었습니다(제과점→인쇄 및 제품 제작업, 주유소→주점업 등). 층위가 달라서였습니다(서울시는 간판 수준, 소상공인 중분류는 통계 수준). 그래서 같은 층위인 소상공인 소분류(1,255종)에서 먼저 찾고 중분류는 거기서 따라오게 했습니다 — 정확 일치 46종, 나머지 53종은 LLM이 소분류 목록에서 판정.

**질문**
1. KSIC를 경유하는 게 정석이 아닐까 생각했습니다. 저희 응답엔 `ksicCd`가 99.9% 채워져 있었지만 서울시 응답 14필드엔 KSIC가 없어서 썼어도 못 이었을 것 같은데, 실무에서는 이럴 때 어떻게 하는지 궁금합니다. 공개된 코드 매핑표를 쓰는 관행이 있을까요?
2. LLM 판정을 데이터 파이프라인에 넣어도 될까요? 53종이 모델 판정이라 근거는 저장해뒀지만, 검수 전에 배포해도 되는 선이 어디인지 여쭤봅니다.
3. 거친 쪽(75종)으로 합치는 선택이 맞았을까요? 서울시 99종 중 69개가 20개 칸으로 뭉쳐집니다. 세분(124종)을 유지하면 점포 수가 여러 업종에 중복으로 실리는데, 어느 쪽이 나은지 궁금합니다.

## 3. 논문 수치를 재현할 때 단위·분모 문제가 있었습니다 🔴

논문의 음식점 최적 밀도 임계값(발달 2.96 / 골목 4.31)을 쓰려다 못 썼습니다. 이유가 세 가지입니다.

**① 단위가 안 적혀 있습니다.** 개/ha인지 개/km²인지 확인이 안 됩니다. 역산해보니 노원 실측값 303.031개/km²를 개/ha로 환산하면 3.03으로, 논문 임계값 2.96과 근접했습니다(국토계획 계열의 개/ha 관행과도 부합). 그럴듯하지만 원문을 못 봐서 추측이라, 이 위에 통과/미달 판정을 올릴 수는 없다고 봤습니다.

**② 단위를 맞춰도 분모가 다릅니다.** 논문은 상권 폴리곤 면적, 저희는 반경 500m 원(0.7854km²)입니다. 원은 도로·주거·공원을 포함해 밀도가 체계적으로 낮게 나와, 단위를 맞춰도 어디를 찍든 임계값 아래로 나옵니다.

**③ 검증할 수단이 없습니다.** 임계값은 폐업 밀도를 종속변수로 한 회귀식의 꼭짓점인데, 폐업 자료는 저희 쪽 담당이 아니라 재현이 안 됩니다.

절대 임계값 대신 서울 상권 분포에서의 백분위로 바꿨는데, 서울시 상권 폴리곤 중앙값(약 0.07km²)과 저희 원(0.7854km²)이 10배 넘게 차이 나 같은 분모 문제가 재현됐습니다. 그래서 서울 상권 1,650곳에 저희와 똑같이 반경 500m 원을 씌워 다시 세는 방식으로 우회했고, 유형별 중앙값이 상식과 맞게 나왔습니다(골목 362.9 < 전통시장 513.1 < 발달 640.4 < 관광특구 855.6, 개/km²).

**질문**
1. 논문에 단위가 없을 때 역산으로 맞추는 접근이 타당할까요, 아니면 이런 정황 일치는 근거로 쓰면 안 되는 종류일까요?
2. 원문을 못 구할 때(유료·비공개) 실무에서는 어떻게 하나요? 저자 문의가 관행일까요?
3. 상권 연구에서 시설 밀도 단위 관행이 개/ha인지 개/km²인지 여쭤봅니다.
4. 면적 정규화 표준이 있을까요? 반경 원 / 상권 폴리곤 / 행정동 중 실무에서 쓰는 기준이 궁금합니다.
5. 논문 값을 못 쓸 때 재현 대신 관측 분포(백분위)로 대체하는 게 타당할까요?
6. 1,650지점 재표본이 과했을까요? 더 싼 방법이 있었을지 궁금합니다.

## 4. 좌표 → 상권 매칭이 근사입니다

서울시 상권영역 API가 폴리곤 없이 중심점과 면적만 줘서, 같은 면적의 원으로 근사해 겹침을 판정합니다. 실제 상권은 길을 따라 길쭉해 원과 다르고, 반경 500m면 여러 상권이 걸립니다. 하나로 줄이지 않고 걸린 것을 전부 내고 있습니다 — 근사 상태에서 하나를 고르면 접경지에서 유형이 뒤집힐 수 있어서입니다.

**질문**
1. 점→구역 매칭을 실무에서는 어떻게 하나요? 폴리곤을 못 구할 때의 관행이 있을까요?
2. 소상공인 쪽은 폴리곤(WKT)을 줍니다. 다른 기관 폴리곤을 쓰는 게 나을까요(식별자 체계가 달라 조인은 안 됩니다)?
3. 여러 개를 그대로 내는 방식이 받는 쪽에 부담을 떠넘기는 건 아닌지 여쭤봅니다.

## 5. 에이전트 독립 원칙과 코드 중복

좌표 변환(WGS84→EPSG:5181, 투영식 40줄)이 유동인구 에이전트에 이미 있었는데, 에이전트끼리 import하지 않기로 해서 복사했습니다. 어긋나면 잡히도록 상대 파일의 검증값으로 시험을 걸어뒀습니다.

**질문**
1. 멀티에이전트에서 공유 유틸리티의 경계를 어디에 두나요?
2. 40줄짜리 코드 중복과 에이전트 간 의존, 어느 쪽이 더 나쁠까요?

## 6. 점수를 주지 않기로 했습니다 — 이 판단이 맞을까요

개폐업 에이전트는 `score` 0~100을 주는데 저희는 지표·순위·비율만 냅니다. 내보내는 지표가 전부 트레이드오프라서입니다(한식 LQ 0.52는 경쟁이 덜한 건지 수요가 없는 건지 알 수 없고, 동종 밀도가 높은 게 집적 이익인지 경쟁 심화인지는 논문에서도 상권 유형에 따라 부호가 뒤집힙니다). 가중치를 정하는 순간 그게 판단이 되고, 판단은 결정 에이전트 몫이라고 봤습니다.

**질문**
1. 이게 책임 회피는 아닐지, 분석 에이전트가 판단을 아예 안 하는 게 맞을지 여쭤봅니다.
2. 셋 중 하나만 점수를 주면 결정 에이전트가 비교하기 어렵지 않을까요(개폐업 score는 "안정성", 저희 쪽은 "경쟁 강도"라 축이 다릅니다)?
