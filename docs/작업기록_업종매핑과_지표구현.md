# 1부. 업종 매핑

## 왜 필요했나

세 에이전트가 **같은 업종을 가리킬 코드가 없었습니다.**

| 에이전트 | 업종 표현 |
| --- | --- |
| 경쟁업체 | 소상공인 중분류 코드 `I201` |
| 개폐업 | 자체 정수 `industry_id` 1~70 |
| 유동인구 | 업종 개념 없음 |
| 결정 | `Category(major, middle)` 자유 문자열 |

`app/schemas.py`의 `Category`가 유일한 접점인데 `major`·`middle` 둘 다 제약 없는 문자열이라
**이미 어휘가 갈려 있었습니다.**

```
한식음식점     (개폐업)
한식 음식점업   (경쟁업체 · mocks)
중식          (결정 에이전트 실제 출력)
```

`schemas.py`의 중복 검사도 casefold만 해서 이 셋을 서로 다른 업종으로 통과시킵니다.

---

## 시도 1 — 이름 유사도 ❌ 실패

두 체계에 **공통 코드가 하나도 없어서**(`I201` vs `CS100001`) 이름 말고는 붙일 단서가 없었습니다.
그래서 문자열 유사도(SequenceMatcher + 문자 bigram 자카드 + 포함 보정)로 7,500쌍을 전부 매겼습니다.

결과가 **못 쓸 수준**이었습니다.

```
0.222  제과점      → 인쇄 및 제품 제작업     ("제"+"제작"이 겹침)
0.222  패스트푸드점  → 스포츠 서비스업        ("푸"↔"포")
0.950  한의원      → 의원                 (부분문자열 우연)
0.817  동물병원     → 병원                 (완전히 다른 업종)
0.650  주유소      → 주점업                ("주" 한 글자)
```

반대 방향 오류도 있었습니다 — **뜻은 맞는데 글자가 안 겹쳐서** 점수가 낮은 것들입니다.

```
0.400  비알코올 음료점업 ↔ 커피-음료      (정답인데 0.4)
0.000  핸드폰         ↔ (못 붙임)        정답은 가전·정보통신장비 소매업
```

### 왜 실패했나

**이름의 층위가 다릅니다.** 서울시는 `제과점`·`네일숍`처럼 가게 간판 수준이고, 소상공인 중분류는
`기타 간이 음식점업`처럼 통계 분류 수준입니다. 같은 층위가 아닌 두 이름을 글자로 비교한 게 잘못이었습니다.

## 시도 2 — 모델이 중분류를 고르게 🟡 나아짐

모델(`claude-sonnet-5`, 엘리스 API)에게 75종 목록을 주고 뜻으로 고르게 했습니다.

**모델이 없는 코드를 지어내지 못하도록** 돌아온 코드를 75종 마스터에 전부 대조했습니다(버려진 코드 0건).
배치 하나가 통째로 빈 응답으로 오는 일이 있어 **빠진 것만 더 작게 잘라 재요청**하는 로직을 넣었습니다.

## 시도 3 — 소분류를 거치기 ✅ 채택

**소분류(1,255종)에 서울시와 같은 층위의 이름이 있다**는 걸 발견했습니다.

```
슈퍼마켓 · 네일숍 · 노래방 · PC방 · 기숙사/고시원 · 독서실/스터디 카페 · 빵/도넛
```

그래서 **소분류에서 찾고, 중분류는 거기서 따라오게** 했습니다.
이러면 **중분류를 사람도 모델도 고르지 않습니다.** 소상공인이 정해둔 값을 그대로 씁니다.

| 단계 | 방법 | 결과 |
| --- | --- | --- |
| 정확 | 서울시 업종명이 소분류에 그대로 있음 | **46종** |
| 모델 | 모델이 **소분류 목록에서** 고름 → 중분류는 원천이 결정 | **53종** |

```
제과점    → 빵/도넛        → I210
커피-음료  → 카페          → I212
의약품    → 약국          → G215
동물병원   → 동물병원       → M111 수의업   (병원 아님)
편의점    → 편의점         → G204
```

### 중간에 버린 단계 하나

처음엔 "부분 일치"를 판정에 썼는데 **흔한 낱말이 엉뚱한 소분류를 잡았습니다.**

```
커피-음료 → "음료" 소매업        (카페가 아니라 생수 파는 가게)
일반의류  → "의류"/이불 수선업    (판매가 아니라 수선)
스포츠 강습 → 스포츠/레크리에이션 "용품 대여업"
```

**판정에서 빼고 모델에게 참고용으로만 넘겼습니다.** 정확 일치만 신뢰합니다.

## 어휘를 75로 정하기까지

매핑이 되고 나니 "그래서 팀 공통 어휘를 몇 개로 할 것인가"가 남았습니다. 두 후보가 있었습니다.

| | 개수 | 설명 |
| --- | --- | --- |
| A | **124** | 서울시 99 + 소상공인 단독 25. 세분 유지 |
| B | **75** | 소상공인 중분류. 서울시가 여기로 접힘 |

### 계산에서 한 번 틀렸습니다

처음에 "125"라고 보고했는데 **124**였습니다. "경로 없는 25종"을 **팀 매핑 99개 기준**으로 세어놓고
서울시 100개에 더해서 생긴 오차입니다. 기준을 맞추면 어느 쪽이든 124입니다.

```
100 서울시 + 24 단독 = 124
 99 서울시 + 25 단독 = 124   (전자상거래업 제외 시, G221이 단독으로 넘어옴)
```

### 75를 골랐을 때 잃는 것

**정확히 알고 골랐습니다.** 서울시 99종이 50개 중분류로 접히므로 **합산은 맞지만 되돌릴 수 없습니다.**

```
공유 중분류 20종에 서울시 업종 69개가 몰림 (99개 중 70%)

제과점 · 패스트푸드점 · 치킨전문점 · 분식전문점  →  I210 하나
일반의원 · 치과의원 · 한의원                   →  Q102 하나
미용실 · 네일숍 · 피부관리실                   →  S207 하나
```

**"치킨집 하세요"라고 못 하고 "기타 간이 음식점업 하세요"가 됩니다.**

### 그럼에도 75가 맞았던 이유

1. **`Category`에 그대로 들어맞습니다.** 소상공인이 대분류 10 / 중분류 75라
   `Category(major, middle)` 두 칸에 딱 맞고, `decision/prompt.md`가 이미 "중분류까지 판단합니다"라고
   적고 있습니다. **새 코드 체계를 발명할 필요가 없었습니다.**
2. **점포 수 공유 문제가 사라집니다.** 75가 더 거칠어서 양쪽 다 **합산**으로 접힙니다.
   124로 갔으면 `I210` 80개가 4개 업종에 똑같이 실려서, 결정 에이전트가 더하면 320개가 됩니다.

## 10·11. 누적 유인 — 합성 점수를 안 만든 이유

Nelson 2원칙은 *"유사·보완 업종의 군집이 분산·고립된 점포보다 흡인력이 크다"* 는 **서술**이라
정해진 수식이 없습니다.

```
major_cluster_count     = 그 업종이 속한 대분류의 점포 수
major_cluster_diversity = 그 대분류 '안'의 유효 중분류 수 (= 1 / HHI)
```

**원본값 둘을 따로 냅니다.** 가중치를 우리가 정하면 그게 곧 판단이 되고, 판단은 결정 에이전트 몫입니다.

구현에서 신경 쓴 것 — 중분류 75회를 도는 루프 **안에서** 대분류 HHI를 매번 다시 세면 75번 재계산이라,
루프에 들어가기 **전에** 한 번만 만들어 두고 조회만 합니다. `hhi`·`effective_categories`·`count_by_major`는
이미 있던 함수를 그대로 썼고 **새 수식은 없습니다.**

0건 업종도 이 두 값은 채워집니다 — 그 업종이 없어도 **대분류가 어떤 상태인지는 말할 수 있어서**입니다.

## 12. 밀도 백분위 — 분모를 맞추는 게 전부였습니다

### 논문 임계값을 왜 못 썼나

발달 2.96 / 골목 4.31이라는 임계값이 있는데 셋 다 걸렸습니다.

1. **단위 미확인** — 개/ha로 환산하면 노원 음식점이 3.03으로 2.96에 가깝지만 원문 없이는 추측
2. **분모가 다름** — 논문은 **상권 폴리곤 면적**, 우리는 **반경 500m 원**(78.5ha)
3. **검증 불가** — 임계값은 **폐업 밀도** 회귀식의 꼭짓점인데 폐업 자료는 개폐업 파트

### 백분위로 바꿨는데 같은 벽이 또 나왔습니다

서울시 상권 자료로 분포를 만들려 했더니 **2번이 그대로 재현**됐습니다.

```
서울시 상권 폴리곤 면적   중앙값 약 0.07 km²
우리 반경 500m 원              0.7854 km²   ← 10배 넘게 차이
```

이대로 백분위를 매기면 **어디를 찍든 최하위**로 나옵니다.

### 그래서 분포를 우리 분모로 다시 만들었습니다

**서울 상권 1,650곳 중심좌표에 우리와 똑같이 반경 500m 원을 씌워** 음식점을 셌습니다.
소상공인 API 1,650회 호출한 1회성 작업이고 결과는 코드 상수입니다.

```
표본 1,650곳 · 최소 0.0 · 중앙 411.3 · 최대 2,108.5

유형별 중앙값   골목상권 362.9 < 전통시장 513.1 < 발달상권 640.4 < 관광특구 855.6
```

**유형별 순서가 상식과 맞는 게 표본이 제대로 잡혔다는 증거**입니다. 이건 우리가 의도한 게 아니라
데이터에서 나온 것이라, 검증으로 씁니다.

```
강남 봉은사로  620.1/km² → 백분위 74.2 (상위 26%)
부산 서면     794.5/km² → null
```

중간에 끊겨도 이어서 돌 수 있게 지점별 결과를 그때그때 파일에 남깁니다.

## 13. 상권 유형 — 하나로 안 고른 이유

**같은 LQ 값의 의미가 유형에 따라 뒤집힙니다.** B2 결론이 *"특화(LQ 높음)는 발달상권에서
생존 위험을 높인다"* 입니다. 유형을 모르면 LQ를 단독 근거로 쓸 수 없습니다.

### 런타임에 서울시 API를 부르지 않습니다

1,650행은 분기마다 바뀌는 **정적 자료**라 한 번 받아 CSV로 동봉했습니다.
새 API 키 의존도, 새 실패 모드도 안 생깁니다.

### 겹침 판정이 근사입니다

영역 API가 **폴리곤을 안 주고 중심점과 면적만** 줍니다. 그래서 상권을 같은 면적의 원으로 근사합니다
(`equivalent_radius_m = sqrt(area / pi)`). 실제 상권은 길을 따라 길쭉해서 원과 다릅니다.

반경 500m면 상권이 여러 개 걸립니다.

```
강남 봉은사로  6곳 — 삼성역(발달) · 강남 마이스(관광특구) · 코엑스(발달) · 휘문고교사거리(발달) …
```

**하나로 줄이지 않고 전부 냅니다.** 근사인 상태로 하나를 고르면 접경지에서 한 끗 차로 뒤집히는데,
그걸 우리가 임의로 정할 근거가 없습니다.

### 좌표 변환은 복사했습니다

서울시 좌표가 EPSG:5181이라 변환이 필요한데, 유동인구 `geo.py`에 이미 있었습니다.
**에이전트끼리 import 안 하기로 해서 정변환 함수만 복사**했고, 두 벌이 어긋나면 잡히도록
`geo.py`에 문서화된 검증값으로 시험을 걸었습니다.

```
오금로 404 (37.5183291, 127.1051123) → (209292.3, 446543.6)
우리 구현과 유동인구 구현이 소수점까지 일치
```

밀도 표본을 만들 땐 역변환이 필요했는데, 역투영식을 따로 두지 않고 **정변환을 뉴턴식으로 되돌렸습니다.**
상권 1,650곳 전수에서 최대 오차 **1.4cm**입니다.

## 곁가지로 나온 것 — 입력 크기 문제

지표를 늘리다 보니 `data`가 52,882자가 됐고, 결정 에이전트가 **빈 객체 `{}`** 를 냈습니다.

`decision/agent.py`가 `model_dump_json()` 한 줄로 전량을 넣고 **자르는 코드가 없어서**,
우리가 요약을 따로 내는 건 소용이 없었습니다. 우리 `data`를 실제로 줄이는 수밖에요.

반경 단계 5→3, 순위 길이 10→5으로 **52,882 → 36,925자(−30%)**. 실제로 다시 돌려
추천 5건·근거 12건이 나오는 걸 확인했습니다.

`by_middle`은 안 건드렸습니다 — LQ·집적 지표가 전부 거기 있어 **결정 에이전트가 실제로 읽는
유일한 블록**입니다.

# 이 작업에서 배운 것

**① 이름이 비슷하다고 같은 것이 아니다.**
층위가 다른 두 분류를 글자로 비교해서 `제과점 → 인쇄 및 제품 제작업`이 나왔습니다.
한 단계 아래(소분류)로 내려가니 같은 층위의 이름이 있었습니다.

**② 모델을 쓰되 모델이 못 지어내게 한다.**
소분류 목록 안에서만 고르게 하고, 돌아온 코드를 전부 마스터에 대조했습니다.
중분류는 어느 경우든 원천이 정한 값입니다.

**③ 분모를 맞추지 않으면 비교가 아니다.**
백분위로 바꿔도 분모가 10배 다르면 어디를 찍든 최하위입니다.
논문 임계값을 못 쓴 이유가 백분위에서 그대로 재현됐습니다.

**④ 판단이 필요한 자리는 비워 둔다.**
누적 유인 합성 점수, 개폐업 점수 가중, 상권 유형 단일화 — 셋 다 우리가 정할 수 있었지만
**가중치를 정하는 순간 그게 판단**이 됩니다. 원본값을 내고 판단은 결정 에이전트에 맡깁니다.

**⑤ 내가 틀린 것은 시험이 잡았다.**
`G212`가 단독 25종에 들어온다고 잘못 적었는데, 그 주장을 시험으로 써놨더니 바로 실패했습니다.
문서에 쓴 주장을 시험으로 옮기면 문서가 늙는 것도 같이 막힙니다.
