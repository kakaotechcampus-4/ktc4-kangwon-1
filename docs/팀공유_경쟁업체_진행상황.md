## 1. 결정 에이전트가 빈 응답을 내던 문제 — 고쳤습니다 🔴→🟢

### 무슨 일이었나

같은 주소(송파 개롱역)로 결정 에이전트를 부르면 **빈 객체 `{}`** 가 돌아왔습니다.

| 입력 | 프롬프트 토큰 | 응답 |
| --- | --- | --- |
| 상권 분석 전량 | 32,585 | `{}` |
| 상권 분석 전량 (재시도) | 40,153 | `{}` |
| `by_radius` 제외 | 7,479 | 정상 |

`finish_reason`이 `stop`이라 잘린 게 아니라 **모델이 빈 객체를 냅니다.**

### 왜 우리가 줄여야 했나

`decision/agent.py`가 이렇게 한 줄로 전량을 프롬프트에 넣습니다.

```python
produced = (generate or generate_decision)(prompt, request.model_dump_json())
```

**자르거나 요약하는 코드가 저장소 어디에도 없습니다.** 그래서 "우리가 `digest`를 따로 낸다"나
"결정이 필요한 필드만 읽는다"는 효과가 없습니다 — 무엇을 더 내든 전량이 들어갑니다.
**우리 `data`를 실제로 작게 만드는 것만** 듣습니다.

### 무엇을 줄였나

반경 단계 5개(50·100·200·300·500) → **3개(50·200·500)**, 순위 배열 길이 10 → **5**.
집계 로직은 그대로고 배열 길이만 짧아집니다.

| | 전 | 후 |
| --- | --- | --- |
| `by_radius` | 23,251자 (44%) | **7,876자 (21%)** |
| **`data` 전체** | **52,882자** | **36,925자** (−30%) |

**실측 결과** — 줄인 뒤 같은 조건으로 다시 돌렸습니다.

```
경쟁업체 data 37,485자 · 요청 전체 38,912자
→ status partial · 추천 5건 · 근거 12건        (이전엔 {})
```

### ⚠️ 유비님께 — 재발할 수 있습니다

`by_middle`이 이제 67%를 차지하는데 **이건 못 줄입니다.** 75행 전수가 계약이고 LQ·집적 지표가
전부 거기 있어 결정 에이전트가 실제로 읽는 유일한 블록입니다.

지역에 따라 다시 커질 수 있습니다. 다음 수단은 각 슬라이스의 `bottom_by_count`(0건 업종 나열 —
`absent_category_count`와 정보 중복) 제거인데, **계약 변경이라 미리 말씀드립니다.**

## 2. 상권 유형 — 넣었습니다 (은우님 자료 덕분)

`trade_areas[]` 배열로 나갑니다.

```json
"trade_areas": [
  {"code": "3001495", "name": "삼성역", "kind": "발달상권", "signgu": "강남구",
   "distance_m": 16.4, "area_m2": 183880.0, "equivalent_radius_m": 241.9}
]
```

**왜 중요한가** — 같은 LQ 값의 의미가 유형에 따라 뒤집힙니다. B2 논문 결론이
"특화(LQ 높음)는 **발달상권에서** 생존 위험을 높인다"입니다. 유형을 모르면 LQ를 단독 근거로 못 씁니다.

**은우님 방식을 그대로 따랐습니다** — `TbgisTrdarRelm` 1,650곳, `TradeArea` 스키마 모양,
면적 등가원 겹침 판정까지. 다만 **좌표 변환 코드를 복사**했습니다(에이전트끼리 import 안 하기로 해서).
`geo.py`에 문서화해두신 검증값(오금로 404 → 209292.3, 446543.6)으로 시험을 걸어뒀으니
한쪽이 바뀌면 우리 시험이 깨집니다.

**하나로 줄이지 않고 걸린 것을 전부 냅니다.** 영역 API가 폴리곤을 안 줘서 원으로 근사하는데,
그 상태로 하나를 고르면 접경지에서 한 끗 차로 뒤집힙니다.

⚠️ **서울 밖은 빈 배열**이고, 서울 안이어도 위례처럼 상권 목록에 없는 신도시는 빈 배열입니다.

## 3. 음식점 밀도 백분위 — 논문 임계값을 대체했습니다

`restaurant_density.seoul_percentile` (0~100, 서울 밖은 `null`)

논문 임계값(발달 2.96 / 골목 4.31)을 못 쓴 이유가 셋이었는데(단위 미확인 · 분모 다름 · 검증 불가),
**관측 분포 그 자체**인 백분위로 바꿨습니다. 유동인구 `benchmark.scale_percentile`과 같은 방식입니다.

### 분모를 맞추는 게 핵심이었습니다

서울시 상권 폴리곤 면적은 중앙값이 약 0.07km²인데 우리 분모는 반경 500m 원 0.7854km²입니다.
**10배 넘게 달라서 그대로 쓰면 어디를 찍든 최하위**가 나옵니다.

그래서 **서울 상권 1,650곳 중심좌표에 우리와 똑같이 반경 500m 원을 씌워** 음식점을 다시 셌습니다.
소상공인 API 1,650회 호출한 1회성 작업이고, 결과는 코드 상수입니다.

```
표본 1,650곳 · 최소 0.0 · 중앙 411.3 · 최대 2,108.5

유형별 중앙값   골목상권 362.9 < 전통시장 513.1 < 발달상권 640.4 < 관광특구 855.6
```

유형별 순서가 상식과 맞는 게 표본이 제대로 잡혔다는 증거입니다.

```
강남 봉은사로  620.1/km² → 백분위 74.2 (상위 26%)
부산 서면     794.5/km² → null
```

## 4. 팀 공통 업종 어휘 — `app/industries` 🔴 **여기가 제일 중요합니다**

### 문제

세 에이전트가 **같은 업종을 가리킬 코드가 없습니다.**

| 에이전트 | 업종 표현 |
| --- | --- |
| 경쟁업체 | 소상공인 중분류 코드 `I201` |
| 개폐업 | 자체 정수 `industry_id` 1~70 |
| 유동인구 | 업종 개념 없음 |
| 결정 | `Category(major, middle)` **제약 없는 자유 문자열** |

`app/schemas.py`의 `Category`가 유일한 접점인데 둘 다 그냥 문자열이라, **이미 어휘가 갈려 있습니다.**

```
한식음식점    (개폐업)
한식 음식점업  (경쟁업체 · mocks)
중식         (결정 에이전트 실제 출력)
```

`schemas.py`의 중복 검사도 casefold만 해서 **이 셋을 서로 다른 업종으로 통과시킵니다.**

### 만든 것

**소상공인 중분류 75종을 공통 어휘로** 삼고 나머지를 거기로 접었습니다.

```
소상공인 상가정보 (전국) ─┐
서울시 상권분석 (서울)    ─┼─→  중분류 75종  ─→  Category(major, middle)
개폐업 70업종           ─┘
```

소상공인 체계가 대분류 10 / 중분류 75라 `Category`의 두 칸에 **그대로 들어맞습니다.**
`decision/prompt.md`가 이미 "중분류까지 판단합니다"라고 적고 있어 새 코드 체계가 필요 없었습니다.

**제후님 `mapping.py`와 같은 모양으로 썼습니다.**

| `mapping.py` | 새 `catalog.py` |
| --- | --- |
| `SERVICE_INDUSTRIES` (70) | `INDUSTRIES` (75) |
| `SEOUL_TO_SERVICE` | `SEOUL_TO_INDUSTRY` (99) |
| `EXCLUDED_SEOUL_INDUSTRIES` | 그대로 |
| `UNSUPPORTED_SERVICE_INDUSTRIES` | `INDUSTRIES_WITHOUT_SEOUL` (25) |
| — | `LEGACY70_TO_INDUSTRY` (마이그레이션용) |

```python
from app.industries import lookup

lookup.find_by_name("한식음식점") == lookup.find_by_name("한식 음식점업")  # True
lookup.from_seoul("CS100005")   # → I210 기타 간이 음식점업
lookup.from_legacy70(33)        # → G202, G203, G222
lookup.as_category("I201")      # → ("음식점업", "한식 음식점업")
```

### 제후님께 — 막혔던 7업종이 풀립니다

`UNSUPPORTED_SERVICE_INDUSTRIES`로 빼두신 7개 중 **6개의 대상이 우리 단독 25종에 있습니다.**

| 팀 업종 | 소상공인 중분류 |
| --- | --- |
| 5 기타 외국식 음식점 | I206 |
| 43 병원·기타 보건서비스 | Q101 병원 · Q104 기타 보건업 |
| 54 마사지·신체관리 | S208 |
| 59 장례·기타 개인서비스 | S210 · S211 |
| 66 광고·시장조사·경영컨설팅 | M105 · M106 · M107 |
| 67 건축·엔지니어링 | M109 |

> 예외는 `26 생활용품 판매점` 하나입니다 — 대상인 `G212`에 서울시 `악기`·`조명용품`이 붙어 있어
> 단독 25종이 아닙니다. (구현 중 시험이 잡아냈습니다)

실제로 강남 반경 500m 1위 업종이 **`M107 경영컨설팅` 424개**였습니다. 서울시 자료만 썼으면
이게 통째로 안 보였을 겁니다.

## 6. 의논할 것

### ① `app/` 최상위에 공유 모듈을 추가했습니다 — 합의 필요

`AGENTS.md` 1항이 **"에이전트 사이 입출력은 `app/schemas.py`가 유일한 기준"** 이라고 적혀 있습니다.
`app/industries/`를 추가한 건 그 범위를 넓히는 일입니다.

역으로 **`schemas.py`를 고칠 수 없으니 별도 모듈 말고 방법이 없었습니다.** 어휘를 한 에이전트
패키지 안에 두면 다른 에이전트가 `from app.agents.commercial_area...`를 하게 되는데 그건 더 나쁩니다.

### ② 70종 → 75종 승격 — 제후님 코드 변경이 따라옵니다

지금은 다리(`LEGACY70_TO_INDUSTRY`)만 제공하고 개폐업 코드는 안 건드렸습니다.
옮기실지, 옮긴다면 언제일지 정해야 합니다.

### ③ 개폐업 점수를 중분류로 어떻게 합칠까요 🔴

개폐업이 주는 건 개수가 아니라 **0~100 점수**인데 70↔75가 **양방향 N:M**입니다.

```
1:1        55종
1:N 쪼개짐   8종   예) 33 자동차·모터사이클·부품 → G202 · G203 · G222
경로 없음    7종   ← 위 §4의 UNSUPPORTED

반대로 한 중분류에 70업종 여럿:
  G213 문화·오락·여가 용품  ← 4개
  R104 유원지·기타 오락     ← 4개
  Q102 의원               ← 3개 (일반의원·치과의원·한의원)
```

**점수 3개를 산술평균하면 틀립니다.** 점포 1개짜리와 100개짜리를 같은 무게로 섞게 됩니다.
서울시 `STOR_CO`로 가중하는 게 맞아 보이는데, **가중 방식은 제후님·유비님과 정할 사항**이라
이번엔 연결표만 내고 `split_count`를 실어뒀습니다.

### ④ 결정 에이전트가 우리 어휘를 안 씁니다 — 유비님

실제 출력이 `중식` · `한식` · `베이커리`로 나옵니다. 우리 75종(`중식 음식점업` 등)과 다릅니다.

`decision/prompt.md`에 **75종 목록을 주입**하고 `agent.py`에서 `lookup.find_by_name()`으로
거르면 풀립니다. `app/industries/lookup.py`에 검사 함수를 준비해뒀습니다.
**`decision/`은 유비님 파일이라 제가 안 건드렸습니다.**

### ⑤ 서울시 99종 중 53건이 모델 판정입니다 — 검수 필요

서울시 업종명이 소상공인 소분류에 그대로 있는 46건은 **조회**라 틀릴 여지가 없습니다.
나머지 53건은 모델이 소분류를 골랐습니다. `근거 소분류` 칸에 무엇을 보고 판단했는지 적혀 있어
빠르게 검수할 수 있습니다.

```
제과점   ← 빵/도넛
커피-음료 ← 카페
의약품   ← 약국
```

`backend/app/industries/data/seoul_to_industry.csv`에서 `match_method=모델`로 걸러 보시면 됩니다.

## 7. 다른 분 코드에서 발견한 것 2건 (제가 안 고쳤습니다)

### ① 개폐업 출력이 팀 계약 검증에 실패합니다 🔴

```python
# 실제로 돌려봤습니다
AgentAnalysis.model_validate(business_lifecycle_for_mediator.json)
→ 1 validation error for AgentAnalysis
  scope.area_code
```

산출물에 `{"area": "개롱역", "area_code": "3120240", "period": "2025Q2"}`가 들어 있습니다.
오케스트레이터에 붙는 순간 터집니다.

### ② 개폐업이 한 해 묵은 분기를 쓰고 있을 수 있습니다

`preprocess.py:24`가 `TARGET_QUARTER = 20252`인데, 서울시 API 실제 최신은 **`20262`(2026년 2분기)**
입니다. 제가 직접 조회해 확인했습니다(2026Q2 = 75,912행).
